The problem

Order the vertices, one greedy pick at a time

You have a graph: dots (vertices) joined by lines (edges). MCS numbers them 1, 2, 3, and so on. Start with nobody chosen. At each step, look at every not-yet-chosen vertex and count how many of its neighbors are already chosen. Pick the vertex with the highest count. If several tie, pick the one with the smallest name. Mark it chosen. Repeat until everyone is numbered. The list you get is a valid MCS ordering.

THE TWIST THAT MAKES IT HARD

The graph is not static. Edges get added and removed between queries. Recomputing the whole ordering from scratch on every change is slow. The discovered algorithm keeps the old ordering and patches it in place, touching only the part that actually changed. The hard question is proving that patch is always correct.

This is not a toy. MCS orderings drive sparse-matrix fill-in and chordal-graph recognition, so getting them fast and correct on changing graphs has real payoff.

The one idea everything hangs on

Freeze the prefix, re-run the suffix

Flip one edge u,v in the current ordering. A vertex's count only changes once one of its endpoints is already chosen. So every greedy pick up to and including the earlier of u and v is unchanged. Only the tail after that point can move. The algorithm keeps the frozen head and re-runs the greedy builder on the tail.

The solution, step by step

A worked example on a 5-vertex graph

Watch the update run on a concrete graph. Vertices are named a, b, c, d, e. The current MCS order is [a, b, c, d, e]. Then we delete the edge {a, b} and patch the order instead of rebuilding it.

  1. 1
    Find the earlier endpoint

    In the order [a,b,c,d,e], a is at position 0 and b at position 1. The earlier endpoint is a (position 0).

  2. 2
    Freeze the prefix through that endpoint

    Keep [a]. The tail after a is thrown out and will be rebuilt greedily on the new graph.

  3. 3
    Re-run greedy on the tail (the decisive pick)

    With only a chosen, b lost its a-b edge so its count drops to 0, but d still touches a, so d has count 1. d strictly beats b, so d goes next. (Continue: c, then b, then e.)

  4. 4
    New valid MCS order

    The order moved from [a,b,c,d,e] to [a,d,c,b,e], and it is still a valid MCS ordering. We touched only the tail, never rebuilt from scratch. That is the whole algorithm.

The solution

Three operations, one invariant

OperationWhat it doesThe invariant it must keep
init(graph) Build the first MCS ordering from an empty graph. Result is a valid MCS ordering.
insert_edge Add edge {u,v}, then freeze prefix + re-greedy suffix. Still a valid MCS ordering.
delete_edge Remove edge {u,v}, same patch. Still a valid MCS ordering.

The invariant is IsMCSOrdering: the ordering lists every vertex exactly once, and at each position the vertex there is the legal MCS pick (max count, lowest name on ties) given what came before. Every operation must preserve it. That single sentence is what the Lean proof is about.

The proof

From empirical to mathematical

The evolutionary search found a candidate that passed thousands of random tests. That is evidence, not proof: a test only shows "no counterexample I tried." To turn that into "correct for every graph," we wrote a machine-checked proof in Lean 4 + mathlib. The machine verifies every step, so there is nowhere to hide.

1
Model the graph

A graph is a symmetric, loop-free adjacency relation on vertices Fin n. The ordering is a plain list.

2
State the invariant

IsMCSOrdering says the list is a legal greedy run. The theorem: each operation preserves it.

3
Prove by induction

The loop invariant (prefix-preservation + greedy suffix) is proved by induction on the loop counter. That is the mathematical heart.

WHY IT IS HONEST (not hand-waving)

The proof's only assumptions are the three standard logical axioms [propext, Classical.choice, Quot.sound]. No sorry (a Lean placeholder for "trust me"), no custom axioms, no unsafe. We re-checked this with #print axioms on every top theorem. A "proof" that leaned on a sorry would be worthless; this one is as solid as Lean's kernel gets.

The crisp core of the proof (22 lines, full strength modulo one named hypothesis) 
/-- Given the prefix is still legal on the new graph,
    re-running the greedy builder on the tail is valid. -/
theorem crisp_mcs_update_valid
    (huv : u ≠ v) (hnodup : order.Nodup)
    (hprefix : PrefixPreserved G' order u v) :
    IsMCSOrdering G' (mcsUpdate G' u v order) := by
  classical
  rw [mcsUpdate, dite_eq_right huv]
  refine greedySuffix_valid G' (order.take (earlierPos order u v + 1))
    (List.Pairwise.take hnodup) ?_
  intro i hi
  -- i is inside the kept prefix, hence before the earlier endpoint.
  have hki : i ≤ earlierPos order u v := ...
  have htake : (...).take i = order.take i := ...
  rw [htake, hget]
  exact hprefix i hlt hki

Read it as the picture: the theorem assumes the frozen prefix is still legal (hprefix) and proves the patched list is a valid MCS ordering. A companion theorem shows that hypothesis is exactly the prefix-preservation lemma, so nothing is lost.

Why the proof got shorter

Elegant is not the same as long

The first proof was correct but 551 lines. We asked why so long, and found two causes, then ran a three-way experiment on how to make it crisp.

CAUSE 1: RE-INVENTED WHEELS

The proof defined its own posOf (where a vertex sits in a list) and five helper lemmas about it. mathlib already ships List.idxOf with the same facts. Swapping it deleted ~71 lines of duplicate math. This was the real bloat.

CAUSE 2: IRREDUCIBLE LOOP FRICTION

The greedy loop was written with its correctness proof baked into its type, so every use needed proof-irrelevance gymnastics. Reshaping the loop into a plain accumulator removed that friction. The grind tactics (omega, simp) were already the right tools.

StrategyIdeaLinesTradeoff
H1 hypothesis split State prefix-preservation as a named hypothesis, prove only the suffix step. 82 Shortest, but the hypothesis carries the real work.
H2 generic greedy Prove one abstract greedy-builder theorem, instantiate to MCS. 391 Reuses across BFS/SCC, but MCS part stays ~127 lines.
H3 reshaped (winner) Same theorem, no hypothesis; reshape the loop so the invariant is near-syntactic. 346 Honest headline: full strength, 28% shorter.
