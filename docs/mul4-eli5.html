The 9-Gate Problem

Unrestricted Boolean multiplicative complexity of 4-term binary multiplication — explained like you're 15, with the actual Lean source.

1The game

Imagine you're building a tiny computer out of logic gates. Two kinds of gates exist:

XOR gates = "are these two bits different?" — these are free.
AND gates = "are both bits ON?" — these cost money.

Your mission: multiply two 4-bit binary polynomials (basically two rows of 4 switches each) and output the 7 answer bits, spending as few AND gates as possible. Mathematicians call the minimum price the multiplicative complexity, or MC for short.

The answer: exactly 9 AND gates. Not 8. Not 10. Nine.

2What the Lean code actually is

Lean is a proof-checking language. You write math like code, and a machine verifies every single step with zero trust. Here's the real definition of a circuit from the repo (UnrestrictedBooleanMul/Circuit.lean):

Circuit.lean — what a "circuit" meansreal source
/-- An unrestricted XOR--AND circuit with exactly `r` AND gates. -/
structure Circuit (m r : Nat) where
  gate  : Fin r → ANF m
  left  : Fin r → ANF m
  right : Fin r → ANF m
  left_mem  : ∀ j, left j  ∈ wireSpace gate j.val
  right_mem : ∀ j, right j ∈ wireSpace gate j.val
  gate_eq   : ∀ j, gate j = left j * right j
Translation: a circuit is just a list of r AND gates. Each gate multiplies a left and right wire, and the two rules left_mem/right_mem say: you may only feed a wire into a gate if you already built it from the inputs or from earlier gates. That last part is the key — earlier gate outputs can be reused as inputs to later gates ("feedback"). That's what makes the circuit unrestricted, and why proving 8 gates impossible is so hard: the circuits can be weird and self-referential.

And here's how "the answer costs MC" is defined:

Circuit.lean — MC = the cheapest working circuitreal source
/-- Unrestricted Boolean multiplicative complexity -/
def multiplicativeComplexity (target) : Nat :=
  if h : ∃ r, HasCircuit target r
  then Nat.find h   -- the smallest r that works
  else 0

notation "MC(" target ")" => multiplicativeComplexity target
Translation: MC(target) = the smallest number of AND gates that can do the job. Nat.find literally means "the smallest r that works". So proving MC(Mul 4) = 9 means proving two things, like a sandwich.

3The sandwich proof

Top slice: 9 is enough

Just show off a 9-gate circuit that works. Done. (It's a Karatsuba trick — the same idea behind fast-multiplication algorithms: trade some additions for fewer multiplications.)

Bottom slice: 8 is impossible

The hard part. You can't test all 8-gate circuits one by one (infinitely many shapes). You need a structural argument that nukes the entire species at once.

The gluing theorem is literally in the code (Circuit.lean):

Circuit.lean — the sandwich rulereal source
theorem mc_eq_of_lower_upper
    (upper : HasCircuit target r)          -- r gates suffice
    (lower : ∀ s, HasCircuit target s → r ≤ s)  -- fewer never work
    : MC(target) = r
Translation: if r gates are enough, and anything smaller is not enough, then MC = r. Exactly. No wiggle room.

4The kill shot: the zombie gate

For the "8 is impossible" half, the proof takes any hypothetical 8-gate circuit, cleans it up into a standard shape ("normalized"), then zooms in on gate number 6 and proves it's a zombie: it must be doing useful work AND must not be doing useful work. That can't happen, so the whole circuit can't exist. This is the heart of the whole result (N4/Main.lean):

N4/Main.lean — the contradictionreal source
/-- The normalized eight-gate state is inconsistent: gate six is useful by
the flag ledger and non-useful by first-jet saturation. -/
theorem normalizedEight_contradiction {C : Circuit 8 8}
    (h : NormalizedEight C) : False :=
  h.gateSix_not_useful h.gateSix_useful

/-- There is no unrestricted eight-AND circuit for four-term Boolean
multiplication. -/
theorem no_eight_gate_circuit : ¬ HasCircuit (Mul 4) 8 := by
  rintro ⟨⟨C, hC⟩⟩
  rcases exists_normalized_eight C hC with ⟨D, hD⟩
  exact normalizedEight_contradiction hD
Translation: line by line: "Suppose an 8-gate circuit exists. Tidy it up into normal form D. Now feed D into the zombie argument: gateSix_useful (one counting method says gate 6 matters) crashes into gateSix_not_useful (a second method says it can't matter). Result: False. The circuit was a myth." The two counting methods have fancy names — "flag ledger" and "first-jet saturation" — but they're just two different ways of measuring how much information a gate can carry.

5The final theorem

Everything plugs into this, the one line the whole paper exists for (N4/Main.lean):

N4/Main.lean — the headlinereal source
/-- The unrestricted Boolean multiplicative complexity of four-term
multiplication is exactly nine. -/
theorem mc_mul_four : MC(Mul 4) = 9 :=
  mc_eq_of_lower_upper mul_four_upper mul_four_lower
Translation: sandwich the upper bound (9-gate circuit exists) with the lower bound (7 and 8 gates impossible) → MC(Mul 4) = 9. The lower-bound half even shows its arithmetic in the code: a dimension count forces gate count ≥ 7, then the zombie argument and an algebraic obstruction kill 7 and 8 one at a time.
Machine-checked: Lean verified every step. The independent rebuild found no sorry (Lean's "trust me" placeholder) and no exotic axioms — only the three standard ones (propext, Classical.choice, Quot.sound).

One honest caveat: Lean proves the code matches the theorem the author wrote. Whether that statement perfectly captures the original 2014 Boyar–Find question still needs an outside human audit.

6So what?

Real-world computers doing private/secure computation (think encrypted messaging math, homomorphic encryption) pay their bills in AND gates. Knowing exactly when sneaky tricks can't save you gates tells cryptographers the true floor price of certain operations. This settles the 4-term case of a 12-year-old open question — 5 terms and up are still unsolved.
