## FAILURE_DESCRIPTION
Failing case is at `sequence_idx: 0`, operation `init`, on the 2x2 all-zero graph
`[[0,0],[0,0]]` with root 0. Expected result:
`{'parent': {0: None}, 'distances': {0: 0}}` — i.e. the result dict should contain
ONLY the root (vertex 0). The candidate's `_result` produced a dict that also
contains vertex 1 (`{'parent': {0: None, 1: None}, 'distances': {0: 0, 1: -1}}`),
so the harness reported `wrong_vertices: [{vertex: 1, expected_distance: -1,
your_distance: -1, your_parent: -1}]`. Note the harness's own `expected_distance`
for vertex 1 is -1, yet it still flags vertex 1 as wrong — the check is
structural: the result must contain exactly the reachable vertices, and
unreachable vertices must be ABSENT from the result dict, not present with
distance -1.

## ROOT_CAUSE
The bug is in `_result` (lines 15-17):

```python
def _result(parent, dist):
    n = len(dist)
    return {'parent': {v: (parent[v] if parent[v] != -1 else None) for v in range(n)},
            'distances': {v: dist[v] for v in range(n)}}
```

It iterates over ALL `n` vertices and includes every vertex in both dicts,
assigning `None`/`-1` to unreachable ones. The expected format (per the failing
case) requires the result dicts to contain only vertices reachable from the
root: `parent` maps each reachable non-root vertex to its parent (root maps to
None), and `distances` maps each reachable vertex to its BFS distance. Unreachable
vertices must be omitted entirely. This is a pure output-formatting bug — the
internal BFS state (`parent`, `dist`, `tree`) is correct; the divergence happens
at the moment `_result` is built, first in `init` (and would recur in
`insert_edge`/`delete_edge` whenever the reachable set changes).

## REPAIR_HINTS
Smallest fix: in `_result`, filter to reachable vertices only:

```python
def _result(parent, dist):
    return {'parent': {v: (parent[v] if parent[v] != -1 else None)
                       for v in range(len(dist)) if dist[v] != -1},
            'distances': {v: dist[v] for v in range(len(dist)) if dist[v] != -1}}
```

Since `dist[v] != -1` iff `v` is reachable from root 0 (root has dist 0, all
others -1 when unreachable), this yields exactly `{'parent': {0: None},
'distances': {0: 0}}` for the failing case. No changes to `_bfs_full`,
`insert_edge`, or `delete_edge` logic are needed for this failure — they all
call `_result` at the end, so fixing `_result` fixes all three entry points.

Do NOT try to "fix" this by changing the internal `dist`/`parent` arrays to
exclude unreachable vertices; the internal arrays must stay length-n with -1
sentinels because `insert_edge`/`delete_edge` index them by vertex id. The fix
belongs solely in the result-serialization step.
