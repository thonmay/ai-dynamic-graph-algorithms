## FAILURE_DESCRIPTION
Case: n=2, root 0. Initial graph is the empty 2x2 matrix (all zeros). The
sequence's first operation is `insert (0, 1)` (sequence_idx 0). After the
insertion the graph is `[[0,1],[0,0]]`, so vertex 1 must be reachable at
distance 1 with parent 0. Expected state: `parent = {0: None, 1: 0}`,
`dist = {0: 0, 1: 1}`. Actual state: `parent = [None, None]`,
`dist = [0, -1]` — vertex 1 is reported unreachable (distance -1, parent
null). The invariant "the tree spans exactly the vertices reachable from r"
is violated: 1 is reachable but missing from the tree.

## ROOT_CAUSE
The bug is in `insert_edge`. The trigger

```python
if dist[u] >= 0 and dist[v] > dist[u] + 1:
```

only fires when the new edge *shortens* an already-reachable vertex. It does
not handle the case where the new edge *makes a previously unreachable vertex
reachable*. In the failing case, before the insertion `dist = [0, -1]`
(vertex 1 unreachable). After inserting (0,1), `dist[v] = -1` and
`dist[u] + 1 = 1`, so the condition `-1 > 1` is False, the whole `if` body
is skipped, and no BFS is ever run. The trailing loop only normalizes
parents of unreachable vertices (`parent[w] = None`), so vertex 1 stays at
`dist -1, parent None`.

The unhandled condition is specifically `dist[v] < 0 and dist[u] >= 0`: the
new edge is the first in-edge into an unreachable vertex, and the algorithm
must start a BFS from `v` (with `dist[v] = dist[u] + 1, parent[v] = u`) to
discover the newly reachable region. (The symmetric case `dist[u] < 0` is
correctly a no-op: an edge out of an unreachable tail cannot help.)

## REPAIR_HINTS
In `insert_edge`, make the trigger also fire when `v` was unreachable and
`u` is reachable. Replace

```python
if dist[u] >= 0 and dist[v] > dist[u] + 1:
```

with

```python
if dist[u] >= 0 and (dist[v] < 0 or dist[v] > dist[u] + 1):
    dist[v] = dist[u] + 1
    parent[v] = u
    _bfs_from(v, graph, dist, parent, n)
```

The existing body already does the right thing: it sets `dist[v] =
dist[u] + 1`, `parent[v] = u`, and runs `_bfs_from(v, ...)`, which relaxes
all outgoing edges of the newly reachable region and pulls in any further
unreachable vertices. The trailing `for w: if dist[w] < 0: parent[w] = None`
loop is then harmless.

Approaches that will not work:
- Relying on the existing `dist[v] > dist[u] + 1` comparison to catch
  `dist[v] == -1`: it does not, because `-1` is numerically smaller than
  any `dist[u] + 1 >= 1`.
- Doing a full BFS from the root on every insertion: correct but defeats
  the research goal of avoiding full recomputation after insertions.
- Only checking `dist[v] < 0` and dropping the shortening branch: would
  miss the case where the new edge shortens an already-reachable vertex
  (e.g., dist[v]=3, dist[u]=0), leaving stale distances.
