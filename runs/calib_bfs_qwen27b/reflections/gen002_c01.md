## FAILURE_DESCRIPTION
Case: 2-vertex directed graph with no edges (all-zero 2x2 adjacency matrix), root 0. Operation: `init` (sequence_idx 0). Expected result: `{'parent': {0: None}, 'distances': {0: 0}}` — only the root is reachable. Actual result reported by the harness: `[-1, -1]`. The harness flags vertex 1 as wrong with `your_parent: -1` (a raw integer sentinel) even though `expected_distance: -1` (unreachable) matches. The invariant "the result spans exactly the vertices reachable from r" is violated at the very first operation: the checked output contains an entry for the unreachable vertex 1 with parent `-1`.

## ROOT_CAUSE
The BFS logic is correct. The bug is a **representation mismatch** between the state's `parent` list and what the grader expects.

After `init` on the empty 2-vertex graph, `_bfs_full` produces:
- `parent = [-1, -1]` (root 0 has parent -1, vertex 1 unreachable has parent -1)
- `dist = [0, -1]`
- `state['result'] = {'parent': {0: None}, 'distances': {0: 0}}` (correctly filtered)

The harness's reported "result" is `[-1, -1]`, which is exactly `state['parent']` verbatim. This means the grader reads the `parent` array directly from the state (not the `state['result']` dict). The grader expects unreachable vertices to have parent `None` (or to be absent), but the candidate stores `-1` as the sentinel for both the root and unreachable vertices in the `parent` list. The grader sees `parent[1] == -1` and flags it as an invalid parent assignment.

The responsible lines are in `_bfs_full`:
```python
parent = [-1] * n          # line: initializes all to -1
dist[0] = 0                # root gets dist 0, but parent[0] stays -1
```
And in `insert_edge` / `delete_edge`, the same `-1` sentinel is used:
```python
parent[v] = -1             # delete_edge: detach subtree
if old_p != -1:            # insert_edge: check for existing parent
```

The `_result` helper correctly maps `-1` → `None` for the dict, but the grader bypasses `_result` and reads `state['parent']` directly.

## REPAIR_HINTS
The smallest fix: change the `parent` list to use `None` instead of `-1` for unreachable vertices (and for the root), so the state's `parent` array is directly grader-compatible.

1. In `_bfs_full`: change `parent = [-1] * n` to `parent = [None] * n`. The root's parent stays `None`.
2. In `insert_edge`: change `if old_p != -1:` to `if old_p is not None:`.
3. In `delete_edge`: change `parent[v] = -1` to `parent[v] = None`. Change `if old_p != -1:` to `if old_p is not None:`.
4. In `_result`: change `parent[v] if parent[v] != -1 else None` to just `parent[v]` (since it's already `None` for unreachable). The `if dist[v] != -1` filter stays.
5. The `dist` list can keep `-1` for unreachable (the grader's `expected_distance: -1` matches that sentinel).

Do NOT change the BFS traversal logic — it is correct. Do NOT try to make the grader read `state['result']` instead of `state['parent']` — the fix is to make `state['parent']` use the right sentinel.
