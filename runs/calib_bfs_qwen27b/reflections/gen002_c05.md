## FAILURE_DESCRIPTION
Graph: 3 vertices, edges (0,1) and (1,2) — i.e. adjacency rows [0,1,0], [0,0,1], [0,0,0]. Root 0.
Operation: `insert (0, 1)` (sequence_idx 0; the initial graph had no edges, so this is the first update).
Expected after update: distances {0:0, 1:1, 2:2}, parents {0:None, 1:0, 2:1}.
Actual: distances {0:0, 1:1, 2:-1}, parents {0:None, 1:0, 2:None}.
Vertex 2 is left unreachable (dist -1, parent None) even though it is reachable via 0→1→2.

## ROOT_CAUSE
In `insert_edge`, the improvement cascade only ever looks at the *old tree children* of the improved vertex, never at its non-tree out-neighbors:

```python
old_children = list(tree[v])
...
while head < len(queue):
    x = queue[head]
    head += 1
    if x == v:
        candidates = old_children
    else:
        candidates = list(tree[x])
    for y in candidates:
        if dist[y] > dist[x] + 1:
            ...
```

Trace on the failing case: before the insert, dist = [0, -1, -1] and `tree[1] = []` (vertex 1 was unreachable, so it had no tree children). After re-parenting 1 to 0 (dist[1] = 1), the cascade queue is `[1]`. Popping x=1, `candidates = old_children = []`, so the loop body never runs. Vertex 2 — which is an *out-neighbor of 1 in the graph* (edge (1,2) existed from the start) but was never a tree child of 1 — is never considered, so it is never discovered.

The invariant "the tree spans exactly the vertices reachable from r" is violated: 2 is reachable but has dist -1 / parent None.

The same flaw exists in the `else` branch: when a deeper vertex x improves, only its old tree children are re-examined, so non-tree out-neighbors of x that could now be improved (or newly reached) are missed.

## REPAIR_HINTS
The cascade must propagate through the graph's out-neighborhood, not just the tree. In `insert_edge`, replace the candidate selection with the actual out-neighbors from `state['adj']`:

```python
while head < len(queue):
    x = queue[head]
    head += 1
    for y in list(state['adj'][x]):
        if dist[y] > dist[x] + 1:
            p = parent[y]
            if p is not None:
                tree[p].remove(y)
                in_tree[y].remove(p)
            dist[y] = dist[x] + 1
            parent[y] = x
            tree[x].append(y)
            in_tree[y].append(x)
            queue.append(y)
```

Notes:
- `old_children` and the `if x == v` special case become unnecessary and can be deleted.
- The `p is not None` guard is needed because an out-neighbor y may currently be unreachable (parent None, dist -1); the old code would crash on `tree[None]` in that case.
- This is a standard BFS-style propagation over `adj` and remains incremental (only vertices whose distance actually improves are enqueued).
- Do NOT try to fix this by pre-scanning `indeg` of v or by only handling the `x == v` case; the same bug recurs one level deeper whenever an improved vertex has non-tree out-neighbors.
- The deletion path's cascade (`for y in list(tree[x])`) has a similar shape but a different semantics (subtree reattachment); verify it separately — the failing case here is purely in the insertion path.
