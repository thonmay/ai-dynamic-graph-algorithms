## FAILURE_DESCRIPTION

Graph (3 vertices, directed): initial graph has only edge 1→2 (row 1 = [0,0,1]). Root is 0.
After `init`, vertex 0 is reachable (dist 0), vertices 1 and 2 are unreachable (dist -1).

Operation: `insert (0, 1)`.

Expected after insert: parent = {0: None, 1: 0, 2: 1}, distances = {0: 0, 1: 1, 2: 2}.
Actual: parent = {0: None, 1: 0, 2: None}, distances = {0: 0, 1: 1, 2: -1}.

Vertex 2 should be reachable at distance 2 (via 0→1→2) but is reported as unreachable.

## ROOT_CAUSE

In `insert_edge`, after re-parenting vertex v (here v=1) to the new parent u (here u=0), the cascade BFS is:

```python
queue = [v]
head = 0
while head < len(queue):
    x = queue[head]
    head += 1
    for y in list(adj[x]):
        if dist[y] > dist[x] + 1:
            ...
```

When x=1 (dist 1) and y=2 (dist -1, unreachable), the condition `dist[y] > dist[x] + 1` evaluates to `-1 > 2`, which is **False**. The unreachable vertex 2 is never discovered because -1 is never greater than any non-negative distance. The cascade silently skips all unreachable out-neighbors.

The identical bug exists in the `delete_edge` cascade:

```python
while head < len(queue):
    x = queue[head]
    head += 1
    for y in list(adj[x]):
        if dist[y] > dist[x] + 1:
```

Here too, a vertex marked unreachable (dist -1) during the deletion will never be rediscovered by the cascade.

## REPAIR_HINTS

In **both** `insert_edge` and `delete_edge`, change the cascade condition from:

```python
if dist[y] > dist[x] + 1:
```

to:

```python
if dist[y] == -1 or dist[y] > dist[x] + 1:
```

This ensures that unreachable vertices (dist -1) are discovered/rediscovered when a reachable vertex x can reach them. The rest of the cascade body (re-parenting, tree/in_tree updates, queue append) already handles the newly-discovered case correctly — it only checks `if p is not None` before removing the old parent, which is a no-op for a previously-unreachable vertex.

This is the minimal fix. No structural changes needed. The `insert_edge` early-return guard (`dist[v] != -1 and dist[u] + 1 >= dist[v]`) is already correct: when `dist[v] == -1` the guard is False and the code proceeds to the cascade, which (after the fix) will properly discover v and its downstream unreachable vertices.
