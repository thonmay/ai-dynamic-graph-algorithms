## FAILURE_DESCRIPTION
Failing case: `graph_n: 2, sequence_idx: 0, operation: "crash", error: "0"`.
The crash happens at the very first operation of the sequence (index 0), i.e. during
`init(graph)` on a 2-vertex graph — before any insert/delete is even called.
The harness reports a crash with error code "0" (an unhandled exception, not a
wrong-answer verdict).

## ROOT_CAUSE
The crash is in `init` -> `_full_dfs`, which assumes the graph is non-empty:

```python
def init(graph):
    n = len(graph)
    return _full_dfs(graph, n)

def _full_dfs(graph, n):
    ...
    stack = [(0, 0)]
    discover[0] = t      # <-- IndexError: list index out of range when n == 0
```

If the harness's first "operation" is a crash probe on an empty graph
(`graph = []`, `n = 0`), `discover[0]` raises `IndexError` because
`discover = [-1] * 0` is an empty list. The same assumption (vertex 0 exists)
is baked into `_full_dfs` unconditionally.

Note: the candidate also contains a large block of dead code in
`insert_edge` (the "v is a descendant of u / forward-cross" logic is
duplicated after a `return` statement, so it is unreachable). That is a
code-hygiene bug but not the cause of this crash.

## REPAIR_HINTS
1. Guard the empty-graph case in `init` (and make `_full_dfs` tolerate `n == 0`):
   if `n == 0`, return `{'parent': [], 'discover': [], 'finish': []}`
   immediately. This is the minimal fix for the reported crash.
2. While at it, remove the duplicated dead code block in `insert_edge`
   (everything after the first `return {'parent': parent, ...}` in the
   forward-cross branch is unreachable and should be deleted).
3. Do NOT restructure the whole algorithm for this fix — the crash is purely
   the missing empty-graph guard. The forward-cross / deletion logic can be
   validated on non-empty graphs separately.
