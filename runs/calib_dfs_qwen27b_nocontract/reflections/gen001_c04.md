## FAILURE_DESCRIPTION
Operation: `init` on the 2x2 graph `[[0,0],[0,0]]` (no edges, root = vertex 0).

- Expected: `{'parent': {0: None, 1: None}, 'discover': {0: 0}, 'finish': {0: 1}}`
  i.e. vertex 0 discovered at time 0, finished at time 1; vertex 1 undiscovered.
- Actual: `{'parent': [-1, -1], 'discover': [1, 0], 'finish': None}`
  i.e. vertex 0 discovered at time 1, and `finish` is `None` (the key is missing
  from the state dict).

Two distinct defects are visible in the output:
1. Discovery time is 1-based (candidate uses `disc[start] = t + 1` with `t`
   starting at 0, so the root gets disc = 1) while the expected convention is
   0-based (root disc = 0).
2. The state dict has no `finish` key at all — the candidate stores finish
   times under the key `'fin'`, but the verifier reads `'finish'`.

## ROOT_CAUSE
The failure is entirely in `init` / `_dfs_from` (no updates are involved;
`sequence_idx` is 0 and the operation is `init`).

Defect 1 — 1-based clock. In `_dfs_from`:

```python
t = state['time']          # 0 at init
...
disc[start] = t + 1        # root gets 1, not 0
t += 1
...
disc[i] = t + 1            # children also 1-based
...
fin[v] = t                 # finish times also shifted by 1
```

The expected convention is 0-based discovery times (root disc = 0, finish =
disc + 1 for a leaf root). The candidate's `t + 1` offset makes every
discovery time one too large.

Defect 2 — wrong state key. `init` builds:

```python
state = {'n': n, 'parent': parent, 'disc': disc, 'fin': fin, 'time': 0}
```

The verifier expects the key `'finish'` (the expected result dict uses
`'finish': {0: 1}`). Because the candidate uses `'fin'`, the verifier's lookup
of `state['finish']` yields `None` in the reported result.

## REPAIR_HINTS
Smallest concrete changes, both in `init`/`_dfs_from` (and every other place
that touches these fields):

1. Rename the state key `'fin'` to `'finish'` in `init` (and update the
   docstring). Every reference to `state['fin']` in `_dfs_from`, `_subtree`,
   and `delete_edge` must use `state['finish']` instead. This is a pure
   rename; no logic changes.

2. Make the clock 0-based. In `_dfs_from`, change:
   - `disc[start] = t + 1` → `disc[start] = t`
   - `disc[i] = t + 1` → `disc[i] = t`
   - Keep `t += 1` after each assignment.
   - `fin[v] = t` → `state['finish'][v] = t` (already correct as a value if
     disc is 0-based: a leaf root with disc=0 gets finish=1, matching the
     expected `{0: 1}`).

   After this change, for the empty 2-vertex graph: disc[0]=0, finish[0]=1,
   disc[1]=0, finish[1]=0 — matching the expected output.

3. Verify the `insert_edge` and `delete_edge` paths still work with 0-based
   times. The `disc[x] == 0` checks for "undiscovered" remain correct (0
   means undiscovered, 1+ means discovered). The `entries.sort(key=lambda w:
   disc[w])` in `delete_edge` still works. No other logic changes needed.

Approaches that will NOT work:
- Simply subtracting 1 from disc values at the end of `init` without also
  fixing the `'fin'` → `'finish'` key rename: the verifier will still get
  `None` for finish.
- Changing only the key rename without fixing the 1-based offset: disc[0]
  will be 1 instead of 0, still failing.

Both fixes are required simultaneously.
