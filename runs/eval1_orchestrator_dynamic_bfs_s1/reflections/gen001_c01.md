## FAILURE_DESCRIPTION
3-vertex directed graph (0-based adjacency matrix):
- 0 -> 1
- 1 -> 0
- 2 -> 0, 2 -> 1

Root = 0. Initial BFS: dist = [0, 1, -1], parent = [None, 0, None].
Update: delete edge (0, 2). Note: edge (0,2) is NOT present in the graph
(matrix row 0 is [0,1,0]), so the deletion is a no-op on the graph.
Expected state after the update: parent = {0: None, 1: 0}, distances = {0: 0, 1: 1}
(vertex 2 unreachable, dist -1).
Actual state: distances = [0, 1, 2], parent[2] = 1.
Wrong vertex: 2 — expected_distance -1, got 2 with parent 1.

## ROOT_CAUSE
The bug is in `insert_edge`. The guard:

```python
if dist[u] != -1 and (dist[v] == -1 or dist[u] + 1 < dist[v]):
```

checks only that `dist[u] != -1`, but does NOT verify that `u` is actually
reachable from the root via a valid parent chain. In the failing sequence,
an earlier deletion cut off vertex 1 (set `dist[1] = -1`, `parent[1] = None`),
but a subsequent insertion of edge (1, 2) fired the guard because `dist[1]`
was still `-1`... wait, that would NOT fire. Let me re-trace.

Actually, the more likely scenario: the state was already inconsistent
BEFORE the failing deletion. The `insert_edge` function can create an
inconsistent state if `dist[u] != -1` but `u`'s parent chain is broken
(e.g., `parent[u]` points to a vertex with `dist = -1`, or `parent[u]` is
None for a non-root vertex). This can happen if a prior `delete_edge`
left the state inconsistent.

The `delete_edge` function's early-exit:

```python
if parent[v] != u:
    return state
```

is correct ONLY if the state is consistent. If the state is inconsistent
(e.g., a vertex has `dist != -1` but its parent chain is broken), the
early-exit can return a corrupted state.

In the failing case, the state before the deletion was:
- dist = [0, 1, 2], parent = [None, 0, 1]
- But vertex 2's parent chain is 2 -> 1 -> 0, which is valid.
- However, vertex 2 is NOT reachable from the root in the actual graph
  (the graph has no path from 0 to 2).

This means the state was already inconsistent before the deletion. The
`insert_edge` function created this inconsistency by propagating from a
vertex that was not actually reachable. The guard `dist[u] != -1` is
insufficient: it must also verify that `u`'s parent chain leads to the
root.

## REPAIR_HINTS
1. In `insert_edge`, after the guard passes, verify that `u` is actually
   reachable by walking the parent chain from `u` to the root:
   ```python
   # Verify u is actually reachable from root
   cur = u
   seen = set()
   while cur is not None and cur != 0:
       if cur in seen or dist[cur] == -1:
           return state  # u not actually reachable; do nothing
       seen.add(cur)
       cur = parent[cur]
   ```
   This ensures we only propagate from genuinely reachable vertices.

2. Alternatively, make `delete_edge` always recompute the affected region
   correctly, even for the early-exit case. The early-exit
   `if parent[v] != u: return state` is safe only if the state is
   consistent. To be robust, remove the early-exit and always run the
   re-rooting logic (which will be a no-op if the state is consistent).

3. The most robust fix: ensure the state is always consistent by making
   both `insert_edge` and `delete_edge` correct. The `insert_edge` guard
   should verify that `u` is reachable (parent chain valid), and the
   `delete_edge` early-exit should be removed or made safe.

4. Approaches that will NOT work:
   - Simply removing the early-exit in `delete_edge` does not fix the
     root cause; the state is already corrupted before the deletion.
   - Changing the guard in `insert_edge` to `dist[u] != -1 and dist[u] + 1 < dist[v]`
     (removing the `dist[v] == -1` case) would prevent inserting edges to
     unreachable vertices, but that is incorrect: inserting an edge from
     a reachable vertex to an unreachable vertex SHOULD make the target
     reachable.
   - The correct guard is `dist[u] != -1 and (dist[v] == -1 or dist[u] + 1 < dist[v])`,
     but it must be paired with a guarantee that `dist[u] != -1` implies
     `u` is actually reachable (i.e., the state is consistent).
