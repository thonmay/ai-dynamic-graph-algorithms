## FAILURE_DESCRIPTION

Operation: `delete (0, 2)` on a 4-vertex directed graph (post-deletion adjacency:
0→3; 1→2; 2→0, 2→3; 3→1, 3→2). Root = 0.

Expected BFS state: `parent = {0:None, 3:0, 1:3, 2:3}`, `distances = {0:0, 3:1, 1:2, 2:2}`.
Actual state produced: `parent = [None, 3, 1, 0]`, `distances = [0, 2, 3, 1]`.

The only wrong vertex is **2**: expected distance 2 with parent 3, but the candidate
reports distance 3 with parent 1. Vertex 2 is reachable from the root via 0→3→2
(distance 2), but the candidate parented it through 1 (0→3→1→2, distance 3).

## ROOT_CAUSE

The bug is in the boundary-seeding loop of `delete_edge`. When the deleted edge is
the parent edge of `v`, the subtree rooted at `v` is cut (distances set to -1) and
then re-rooted by a "multi-source BFS from the boundary". The seeding code is:

```python
q = deque()
for w in range(n):
    if in_sub[w]:
        continue
    if dist[w] == -1:
        continue
    for x in adj[w]:
        if in_sub[x] and dist[x] == -1:
            dist[x] = dist[w] + 1
            parent[x] = w
            q.append(x)
```

Two defects combine here:

1. **Sources are seeded in vertex-index order, not distance order.** The outer loop
   `for w in range(n)` visits boundary vertices in increasing id, so the *first*
   boundary vertex (by id) that has an edge into a given subtree vertex `x` is the
   one that wins, regardless of its distance.
2. **The `dist[x] == -1` guard makes the first writer final for that vertex.** Once
   some `w` sets `dist[x]`, no later (closer) boundary vertex can overwrite it,
   because the guard now fails.

In the failing case the subtree is `{2}` (the deleted edge (0,2) was 2's parent
edge). The boundary vertices with an edge into 2 are `w=1` (dist 2) and `w=3`
(dist 1). The loop hits `w=1` first (id 1 < id 3) and sets `dist[2]=3, parent[2]=1`.
When `w=3` is reached, `dist[2]` is already 3 (not -1), so the guard skips it and
2 is never re-parented to the closer vertex 3. The subsequent BFS propagation
cannot fix this either, because it only *decreases* distances and 3→2 would give
`dist[3]+1 = 2 < 3` — but 3 is outside the subtree and is never enqueued as a
source, so that edge is never relaxed. Result: 2 stuck at distance 3 via parent 1.

This violates the BFS invariant "the parent of v sits one BFS distance closer to
the root than v does" (parent 1 is at distance 2, one less than 3, so the local
parent-distance relation holds, but the *distance itself* is not the true BFS
distance, and the true closer in-neighbor 3 was ignored).

## REPAIR_HINTS

The minimal fix is to make the boundary seeding a true multi-source BFS that picks
the **minimum** boundary distance for each subtree vertex, not the first one by
vertex id. Concretely, in `delete_edge`, replace the seeding block with:

- First pass: for every outside vertex `w` with `dist[w] != -1` and every
  `x in adj[w]` with `in_sub[x]`, compute `best = dist[w] + 1` and set
  `dist[x] = min(dist[x], best)` (initially -1), tracking the argmin `parent[x] = w`.
  This guarantees each subtree vertex is seeded at the true minimum boundary
  distance.
- Then enqueue every `x` whose `dist[x]` was set (i.e. became != -1) and run the
  existing propagation BFS unchanged.

Equivalently, seed *all* boundary edges into the queue up front (pushing `(x, w)`
for every boundary edge) and let a standard BFS with a `dist[x] == -1`-on-pop
check resolve ties by distance; but the explicit min-pass is simpler and less
error-prone.

Do **not** try to fix this by reordering the `for w in range(n)` loop to be sorted
by `dist[w]` — that still fails when a single subtree vertex is reachable from two
boundary vertices and the closer one is processed but the `dist[x]==-1` guard has
already been tripped by an even earlier same-distance or the ordering is not a
stable distance order across the whole boundary. The robust fix is the explicit
min over all boundary in-neighbors before any BFS propagation.

Note the `insert_edge` path is not implicated in this failure (distances only
decrease on insertion and the propagation correctly relaxes strictly-smaller
distances); the defect is isolated to the deletion boundary seeding.
