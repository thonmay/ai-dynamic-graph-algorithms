# Reflection: gen002_c04 — dynamic_bfs

## FAILURE_DESCRIPTION

- Graph (3x3, directed, root 0):
  ```
  0 -> 1
  1 -> 2
  ```
  i.e. adj = [[0,1,0],[0,0,1],[0,0,0]].
- Operation: `insert (0, 1)` — a no-op insertion (edge 0->1 already present; the harness flips the entry, which is already 1).
- Expected state: parent = {0: None, 1: 0, 2: 1}, distances = {0: 0, 1: 1, 2: 2}.
- Actual state: parent = [None, 0, None], distances = [0, 1, -1].
- Wrong vertex: 2 — expected distance 2 / parent 1, got distance -1 / parent None.

## ROOT_CAUSE

The bug is in `insert_edge`. The guard

```python
dv = dist[v] if dist[v] != -1 else INF
if dist[u] != -1 and dist[u] + 1 < dv:
```

is correct for a *genuinely new* edge, but the harness may call `insert_edge` on an edge that is already present (a no-op flip). Here u=0, v=1, dist=[0,1,2], so `dist[u]+1 = 1` is **not** `< dv = 1` and the guard is false — the function should simply return the state unchanged.

However, the state is still corrupted before that guard is even reached, because the candidate mutates `state['adj']` in place at the top:

```python
adj = state['adj']
adj[u][v] = 1
```

That alone is harmless for this case (the entry was already 1). The real corruption comes from the fact that the guard *is* the only protection, and the code path that runs when the guard is true is itself broken for the "v already reachable at the same distance" boundary — but in this specific failing case the guard is false, so the returned state should be the input state.

Tracing precisely:
1. `init` on the graph gives parent=[None,0,1], dist=[0,1,2]. Correct.
2. `insert_edge(graph,(0,1),state)`:
   - `adj[0][1] = 1` (no change).
   - `dv = 1`, `dist[u]+1 = 1`, guard `1 < 1` is **False**.
   - The function falls through to `state['parent'] = parent; state['distances'] = dist; state['adj'] = adj; return state`.

So the code as written should return the correct state for this exact trace... which means the divergence must come from an *earlier* update in the sequence that left the state already wrong, and this insert (0,1) is merely the first update the harness reports as wrong (sequence_idx 0 is the index into the update list, and the "graph" shown is the graph *after* the update).

Re-reading the case: `"sequence_idx": 0`, `"operation": "insert (0, 1)"`, and the shown `graph` is the post-update graph. The pre-update graph therefore had adj[0][1] = 0, i.e. only edge 1->2 existed. Pre-update state from `init` on [[0,0,0],[0,0,1],[0,0,0]]: parent=[None,None,None], dist=[0,-1,-1].

Now `insert_edge((0,1))`:
- `adj[0][1] = 1`.
- `dv = INF` (dist[1] = -1), `dist[0]+1 = 1 < INF` → guard TRUE.
- Pre-seed: `dist[1] = 1`, `parent[1] = 0`.
- Frontier: `[1]` plus every reachable w with adj[w][1]. Only w=0 is reachable and adj[0][1]=1, so frontier = [1, 0].
- `_bfs_from_frontier(adj, [1,0], dist=[0,1,-1], parent=[None,0,None], n=3)`:
  - Pop 1: du=1, row=adj[1]=[0,0,1]. v=2: 1+1=2 < -1? **No** — the comparison is `du + 1 < new_dist[v]` with `new_dist[2] = -1`, and `2 < -1` is False. **Vertex 2 is never relaxed.**
  - Pop 0: du=0, row=adj[0]=[0,1,0]. v=1: 0+1=1 < 1? No.
  - Result: dist stays [0,1,-1], parent stays [None,0,None].
- The "propagate reachability from v to old descendants" block runs: children of 1 in the (new) parent list — none, since parent[2] is None. So nothing is fixed.

**Root cause, precisely:** `_bfs_from_frontier` (and `_bfs_bounded`) use the sentinel `-1` for "unreachable" directly inside the relaxation test `du + 1 < new_dist[v]`. Since `-1` is numerically smaller than any non-negative distance, an unreachable vertex (dist -1) can **never** be improved by the relaxation — the condition is always false. The bounded-BFS helpers therefore only work when every vertex they need to reach is already reachable; they cannot make a previously-unreachable vertex reachable. In `insert_edge`, the pre-seed fixes v itself, but v's descendants (like vertex 2, reachable only through v) remain at -1 and are never discovered.

The responsible lines:

```python
# in _bfs_from_frontier (and _bfs_bounded):
if row[v] and du + 1 < new_dist[v]:
```

with `new_dist[v] == -1` for unreachable vertices.

## REPAIR_HINTS

Smallest fix: normalize the sentinel before the bounded BFS. In `insert_edge`, before calling `_bfs_from_frontier`, map every `-1` in the working `dist` list to `INF` (and back to `-1` after the BFS for vertices still at INF). Equivalently, change the relaxation in `_bfs_from_frontier`/`_bfs_bounded` to treat -1 as infinity:

```python
cur = new_dist[v] if new_dist[v] != -1 else INF
if row[v] and du + 1 < cur:
    new_dist[v] = du + 1
    ...
```

and after the BFS, convert any remaining INF back to -1. This makes the frontier BFS able to discover vertex 2 (dist 2, parent 1) in the failing case.

The same -1-vs-INF bug pattern should be checked in `delete_edge`: there the code explicitly sets subtree vertices to `INF` before its BFS, so that path is safe, but the relaxation `dx + 1 < new_dist[y]` there relies on that pre-marking — keep it.

Approaches that will NOT work:
- Relying on the "propagate reachability from v to old descendants" post-pass in `insert_edge`: it only walks the *current* parent tree, so descendants that were unreachable (parent None) are invisible to it. It cannot fix the discovery problem.
- Adding v's old descendants to the frontier: they have dist -1 and no valid parent, so seeding them does not help unless the -1/INF sentinel bug is fixed first.
- A full recompute in `insert_edge` would be correct but defeats the research goal (avoid full recompute after updates); the sentinel fix is the minimal correct change.
