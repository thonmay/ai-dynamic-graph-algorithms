## FAILURE_DESCRIPTION
Failing case: 2-vertex directed graph, root 0. The graph passed to the update is
`[[0,1],[0,0]]` (edge 0->1 present). Operation: `insert (0, 1)`.
Expected state: `parent = {0: None, 1: 0}`, `distances = {0: 0, 1: 1}`.
Actual state: `parent = [None, None]`, `distances = [0, -1]` — vertex 1 is
reported unreachable.

Tracing the code:
- `insert_edge` copies `adj` from the passed graph, so `adj[0][1] == 1` (the new
  edge IS present in the matrix).
- The defensive consistency check passes (parent[1] is None and dist[1] == -1,
  so no inconsistency is flagged).
- The improvement test `dist[u] != -1 and dist[u] + 1 < dist[v]` is True
  (0 + 1 < -1), so `_bfs_bounded(adj, v=1, dist, parent, n)` is called.
- Inside `_bfs_bounded`, `new_dist[start] == -1` so it sets
  `new_dist[1] = 0` and `new_parent[1] = None` — treating vertex 1 as a NEW
  ROOT at distance 0.
- The BFS then explores 1's out-neighbors (none), so the result is
  `distances = [0, 0]`, `parent = [None, None]`.
- The verifier then reports vertex 1 with distance 0 / parent None as wrong
  (expected distance 1, parent 0).

## ROOT_CAUSE
`_bfs_bounded` (lines ~20-40) is written for the "shorten an already-reachable
vertex" case, where `start` keeps its old distance and the BFS only relaxes
strictly smaller distances. It does NOT handle the "make an unreachable vertex
reachable" case: when `new_dist[start] == -1` it sets `new_dist[start] = 0`
and `new_parent[start] = None`, i.e. it re-roots the BFS at `start` instead of
attaching `start` to its new in-neighbor `u` at distance `dist[u] + 1`.

The responsible lines:
```python
if new_dist[start] == -1:
    new_dist[start] = 0
    new_parent[start] = None
    changed.add(start)
```
This is only correct if `start` is the actual root (vertex 0). For any other
vertex that becomes reachable via the inserted edge (u, v), the correct
initialization is `new_dist[v] = dist[u] + 1` and `new_parent[v] = u`, and the
bounded BFS should then continue from v to propagate improvements to v's
descendants.

## REPAIR_HINTS
In `insert_edge`, split the two cases before calling `_bfs_bounded`:

1. **v already reachable** (`dist[v] != -1` and `dist[u] + 1 < dist[v]`):
   keep the current `_bfs_bounded` behavior (start keeps its old distance,
   BFS relaxes strictly smaller distances). This is already correct.

2. **v unreachable** (`dist[v] == -1` and `dist[u] != -1`):
   initialize `new_dist[v] = dist[u] + 1`, `new_parent[v] = u`, then run the
   bounded BFS from v (with the same "only relax if strictly smaller" rule)
   to propagate the new reachability to v's descendants. Do NOT set
   `new_dist[v] = 0` / `new_parent[v] = None`.

Concretely, either:
- Add a parameter to `_bfs_bounded` like `initial_dist` / `initial_parent`
  for the start vertex, or
- Handle the unreachable case inline in `insert_edge` by setting
  `dist[v] = dist[u] + 1`, `parent[v] = u` before calling `_bfs_bounded`
  (and removing the `if new_dist[start] == -1` block, or guarding it to only
  fire when `start == 0`).

Approaches that will NOT work:
- Simply changing the `if new_dist[start] == -1` block to use `dist[u] + 1`
  without also passing `u` into `_bfs_bounded` — the function has no access
  to `u`.
- Calling `_rebuild` on every insertion — correct but defeats the purpose of
  the dynamic algorithm (the research goal is to avoid full recomputation).
