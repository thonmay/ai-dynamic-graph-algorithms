## FAILURE_DESCRIPTION
3-vertex directed graph, root 0. Pre-update graph has only edge 1→2 (edge 0→1 is absent). `init` yields dist=[0,-1,-1], parent=[None,None,None]. Operation: `insert_edge(graph, (0,1), state)`. Expected after the insert: dist=[0,1,2], parent=[None,0,1]. Actual returned: dist=[0,1,1], parent=[None,0,1]. Vertex 2 has distance 1 instead of 2 (its parent 1 is at distance 1, so the parent must be one closer, i.e. dist 0 — violated).

## ROOT_CAUSE
Two compounding bugs in `insert_edge`'s handling of a newly reachable vertex v:

1. **`_bfs_from_frontier` (and `_bfs_bounded`) never relax into unreachable vertices.** The relaxation test is `if row[v] and du + 1 < new_dist[v]`, but unreachable vertices carry `new_dist[v] = -1`, and `du + 1 < -1` is always False. So when v=1 becomes reachable, its descendant 2 (still -1) is never discovered by the frontier BFS. The -1 sentinel is treated as a real, tiny distance instead of infinity.

2. **The `_bfs_unbounded(adj, v, n)` fallback assigns distances relative to v-as-root (off by `dist[v]`), and the "restore" only fixes v itself.** In the trace: `_bfs_unbounded(adj, 1, 3)` returns d2=[-1,0,1], p2=[None,None,1]. The merge loop sets dist[2]=1, parent[2]=1 (and dist[1]=0, parent[1]=None). The code then restores only v: `dist[v] = dist[u] + 1; parent[v] = u` → dist[1]=1, parent[1]=0. But vertex 2 keeps the off-by-one distance 1 (true value 2). The follow-up `frontier2`/`frontier3` re-runs of `_bfs_from_frontier` cannot repair it: the relaxation condition only fires on strict improvement, and the wrong-but-smaller value 1 is not improved by the correct value 2.

The final state dist=[0,1,1] matches the reported failure exactly.

## REPAIR_HINTS
Smallest fix: make the bounded/frontier BFS treat -1 as infinity. In `_bfs_from_frontier` and `_bfs_bounded`, change the relaxation condition to treat -1 as INF, e.g.:
```python
target = new_dist[v] if new_dist[v] != -1 else INF
if row[v] and du + 1 < target:
```
This alone lets the frontier BFS discover v's newly reachable descendants (vertex 2 gets dist 2, parent 1) with correct absolute distances, since the frontier vertices keep their true root-relative distances.

Then the `_bfs_unbounded(adj, v, n)` fallback block (and its `dist[v] = dist[u] + 1; parent[v] = u` restore, and the duplicated frontier2/frontier3 re-runs) becomes unnecessary and should be removed — it is the source of the off-by-dist[v] distances. If a fallback for newly reachable vertices is kept, it must add `dist[v]` to every distance it assigns (i.e., use `dist[v] + d2[x]`), not just restore v's own entry.

Approaches that will NOT work:
- Re-running the frontier BFS more times (as the code already does with frontier2/frontier3) cannot fix a distance that is already too small; the strict-improvement condition never increases a distance.
- Restoring only v's distance after the plain BFS from v leaves all of v's descendants off by `dist[v]`.
