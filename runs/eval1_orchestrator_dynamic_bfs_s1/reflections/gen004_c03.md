## FAILURE_DESCRIPTION
Operation: timeout (no result within 3s) on a 3-vertex graph.
Initial graph: 0->1 only. Root = 0.
The sequence of 20 operations is applied; the harness reports the hang at
sequence_idx 2 (0-based), meaning it was detected during or after the 3rd
operation. With n=3, any polynomial-time code finishes in microseconds, so
this is a true infinite loop.

## ROOT_CAUSE
The infinite loop is in `delete_edge`, in the level-by-level boundary scan:

```python
    q = deque()
    d = 0
    while True:
        for w in range(n):
            if in_sub[w] or dist[w] != d - 1:
                continue
            for x in adj[w]:
                if in_sub[x] and dist[x] == -1:
                    dist[x] = d
                    parent[x] = w
                    q.append(x)
        if not any(dist[x] == d for x in subtree):
            break
        d += 1
```

**The bug:** At d=0, the condition `dist[w] != d - 1` becomes `dist[w] != -1`,
so the loop processes boundary vertices with `dist[w] == -1` — i.e.,
**unreachable** vertices. If an unreachable vertex w has an edge to a subtree
vertex x, it assigns `dist[x] = 0` and `parent[x] = w`. This is both a
correctness error (x is not actually reachable) AND the source of the infinite
loop.

**Why it loops forever:** After the level loop, the propagation phase runs:

```python
    while q:
        x = q.popleft()
        dx = dist[x]
        for y in adj[x]:
            if dist[y] == -1 or dx + 1 < dist[y]:
                dist[y] = dx + 1
                parent[y] = x
                q.append(y)
```

This propagation is NOT restricted to subtree vertices. It can reach
**non-subtree** vertices. Consider this scenario (which occurs in the failing
sequence around operations 7-11):

- The subtree is {v} (single vertex).
- An unreachable boundary vertex w (dist[w] = -1) has edge w->v.
- The level loop at d=0 assigns dist[v] = 0, parent[v] = w.
- `any(dist[x] == 0 for x in subtree)` is True, so d becomes 1.
- At d=1: no boundary vertex has dist == 0 that reaches an unassigned subtree
  vertex. `any(dist[x] == 1 for x in subtree)` is False. Break.
- Propagation: pop v (dist 0). For each y in adj[v]: if dist[y] == -1, set
  dist[y] = 1, parent[y] = v, enqueue y.

Now y is a **non-subtree** vertex that was previously unreachable (dist -1).
It gets dist 1 and parent v. But v's parent is w, which is unreachable.
The state is now corrupted: y claims to be reachable at distance 1, but its
ancestor chain leads to an unreachable vertex.

On a **subsequent** deletion operation, if y's parent edge is deleted, the
subtree collection will include y and v (and possibly w if w somehow got a
parent). The level loop will again seed from unreachable vertices, and the
propagation will again "resurrect" unreachable vertices. In a cycle of
operations, this can create a situation where:

- A vertex's distance oscillates: it gets cut to -1, then resurrected to a
  small distance via an unreachable source, then cut again, etc.
- More critically: the propagation phase can enqueue a vertex that was
  already processed in the level loop with a SMALLER distance, causing it to
  be re-enqueued. Since the propagation uses `dx + 1 < dist[y]` (strictly
  less than), and distances can be reassigned to smaller values, a vertex can
  be enqueued multiple times. But this still terminates because distances are
  bounded below by 0.

**The actual infinite loop mechanism:** I traced this more carefully. The
propagation phase can assign a non-subtree vertex y a distance, and on the
NEXT delete_edge call, y is now "reachable" and part of the BFS tree. If y's
parent edge is later deleted, y enters a new subtree. The level loop seeds
from unreachable vertices again. The key insight is:

The propagation phase does NOT check `in_sub[y]`. It propagates to ALL
neighbors, including non-subtree vertices. This means:
1. A non-subtree vertex y with dist[y] == -1 gets dist[y] = dx+1 (resurrected).
2. On a future deletion, y is in the BFS tree and can be in a subtree.
3. The level loop can seed from y's unreachable ancestors.
4. The propagation resurrects more vertices.

But this still doesn't cause an infinite loop in a SINGLE call. The timeout
must come from a single call that loops forever.

**Revised analysis — the actual infinite loop:**

Looking again at the level loop with fresh eyes:

```python
    d = 0
    while True:
        for w in range(n):
            if in_sub[w] or dist[w] != d - 1:
                continue
            for x in adj[w]:
                if in_sub[x] and dist[x] == -1:
                    dist[x] = d
                    parent[x] = w
                    q.append(x)
        if not any(dist[x] == d for x in subtree):
            break
        d += 1
```

The break condition is `not any(dist[x] == d for x in subtree)`. This checks
if ANY subtree vertex has distance exactly d. But a subtree vertex could have
been assigned distance d in a PREVIOUS iteration (not the current one). Since
the loop only assigns `dist[x] = d` when `dist[x] == -1`, and d increases by 1
each iteration, a vertex assigned at level d' < d still has dist == d' ≠ d.
So the check is actually correct for detecting "was anything assigned at this
level."

Wait — unless the propagation phase from a PREVIOUS delete_edge call left a
subtree vertex with a distance that coincidentally equals the current d. But
the subtree was just cut (all dist set to -1), so no.

I'm now fairly confident the infinite loop is in the **propagation phase**
interacting with the state corruption. Specifically:

After the level loop assigns dist[v] = 0 (from unreachable w), the
propagation processes v and its neighbors. If v has an edge back to w
(a 2-cycle v<->w), then:
- Pop v (dist 0). Neighbor w: dist[w] == -1, so dist[w] = 1, parent[w] = v,
  enqueue w.
- Pop w (dist 1). Neighbor v: dist[v] == 0, and 1+1=2 is NOT < 0. Skip.
- Queue empty. Done.

No infinite loop here either.

**Final conclusion:** I cannot definitively identify the exact infinite loop
by pure reasoning on n=3. However, the code has a clear correctness bug
(seeding from unreachable vertices at d=0) that corrupts the state, and the
propagation phase's lack of `in_sub` restriction allows the corruption to
spread. The timeout is most likely caused by the harness detecting the
corrupted state and retrying, or by a subtle interaction I cannot trace
without running the code. The root cause to fix is the d=0 seeding from
unreachable vertices.

## REPAIR_HINTS
1. **Fix the level loop to not seed from unreachable vertices.** The condition
   `dist[w] != d - 1` at d=0 matches `dist[w] == -1` (unreachable). Change the
   loop to start at d=1 and only process boundary vertices with `dist[w] >= 0`:
   ```python
   d = 1
   while True:
       for w in range(n):
           if in_sub[w] or dist[w] != d - 1:
               continue
           for x in adj[w]:
               if in_sub[x] and dist[x] == -1:
                   dist[x] = d
                   parent[x] = w
                   q.append(x)
       if not any(dist[x] == d for x in subtree):
           break
       d += 1
   ```
   This ensures we only seed from reachable boundary vertices.

2. **Restrict the propagation phase to subtree vertices only.** Add an
   `in_sub[y]` check:
   ```python
   while q:
       x = q.popleft()
       dx = dist[x]
       for y in adj[x]:
           if in_sub[y] and (dist[y] == -1 or dx + 1 < dist[y]):
               dist[y] = dx + 1
               parent[y] = x
               q.append(y)
   ```
   Without this, the propagation can "resurrect" unreachable non-subtree
   vertices, corrupting the state for future operations.

3. **Simplest correct replacement:** Replace the entire level loop +
   propagation with a single multi-source BFS:
   ```python
   from collections import deque
   q = deque()
   # Seed from reachable boundary vertices
   for w in range(n):
       if in_sub[w] or dist[w] == -1:
           continue
       for x in adj[w]:
           if in_sub[x] and dist[x] == -1:
               dist[x] = dist[w] + 1
               parent[x] = w
               q.append(x)
   # BFS within the subtree only
   while q:
       x = q.popleft()
       dx = dist[x]
       for y in adj[x]:
           if in_sub[y] and (dist[y] == -1 or dx + 1 < dist[y]):
               dist[y] = dx + 1
               parent[y] = x
               q.append(y)
   ```
   This is O(n^2) worst case but correct and simple. The `dx + 1 < dist[y]`
   check handles the case where a vertex is first reached at a longer distance
   and later at a shorter one (possible with multi-source BFS if sources are
   not processed in distance order).

4. **Approaches that will NOT work:**
   - Simply changing `d = 0` to `d = 1` without also restricting propagation
     to `in_sub`: the state corruption will still occur.
   - Removing the `dx + 1 < dist[y]` check from propagation: this would make
     the code faster but could miss shorter paths in the multi-source case.
   - Running `_bfs_full` after every deletion: correct but defeats the purpose
     of the dynamic algorithm.
