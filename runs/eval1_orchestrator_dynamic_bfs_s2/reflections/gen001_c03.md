## FAILURE_DESCRIPTION
Case: n=2, root 0, initial graph empty (both rows all zeros). Operation: `insert (0, 1)`.
Expected after the update: `parent = {0: None, 1: 0}`, `distances = {0: 0, 1: 1}`.
Actual: `parent[1] = None`, `distances[1] = -1` (vertex 1 reported unreachable).
The verifier's result string `[None, None]` is the parent list; vertex 1's distance is -1.

## ROOT_CAUSE
In `insert_edge`, the propagation guard compares the new candidate distance against the stored distance using a strict `<`:

```python
cand = dist[u] + 1
if cand < dist[v]:
    dist[v] = cand
    parent[v] = u
    heapq.heappush(heap, (cand, v))
```

Unreachable vertices are encoded as `dist[v] = -1` (see `_bfs_from_root` and the deletion repair loop, which sets `dist[x] = -1`). Since `-1` is numerically *smaller* than any real distance, `cand < dist[v]` is always False for an unreachable `v` (e.g. `cand = 1`, `dist[v] = -1` → `1 < -1` is False). So an insertion that makes a previously unreachable vertex reachable never updates it, and the heap stays empty, so no propagation happens at all.

Trace on the failing case:
1. `init` on the empty graph: `dist = [0, -1]`, `parent = [None, None]`.
2. `insert_edge((0,1))`: `adj[0].add(1)`, `rev[1].add(0)`. `dist[u]=dist[0]=0` (not -1, so no early return). `cand = 1`. Guard `1 < dist[1]` → `1 < -1` → False. Nothing is pushed, nothing is updated.
3. Returned state still has `dist[1] = -1`, `parent[1] = None`. Divergence occurs exactly at this guard.

The same bug pattern exists in the propagation loop:

```python
for y in adj[x]:
    if nd < dist[y]:
```

which also fails to relax an unreachable `y` (`nd < -1` is False).

## REPAIR_HINTS
Treat `-1` as "infinity" in every comparison in `insert_edge`. Minimal fix:

1. In the initial guard, change the condition to:
   ```python
   if dist[v] == -1 or cand < dist[v]:
   ```
2. In the propagation loop, change:
   ```python
   if nd < dist[y]:
   ```
   to:
   ```python
   if dist[y] == -1 or nd < dist[y]:
   ```

Alternatively, normalize the encoding: use `INF` (or `None`) for unreachable in the internal `dist` list and only convert to `-1` when returning the state. But since the state contract requires `-1` in the returned `distances` list and the state is the same dict that's returned, the simplest correct fix is the explicit `-1` checks above.

Note: the deletion path does NOT have this bug — it uses a separate `newdist` dict with `INF` as the default via `newdist.get(x, INF)`, so unreachable vertices are handled correctly there. The bug is confined to `insert_edge`.

Approaches that will NOT work:
- Changing `-1` to `0` for unreachable: breaks the root (dist 0) and makes the `dist[u] == -1` early-return check wrong.
- Only fixing the initial guard without fixing the propagation loop: the first hop would work but multi-hop propagation through newly reachable vertices would still fail.
