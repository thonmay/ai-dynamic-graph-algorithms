## FAILURE_DESCRIPTION
Graph: 2 vertices, initial adjacency matrix all zeros (no edges), root 0.
Operation: insert (0, 1).
Expected after update: parent = {0: None, 1: 0}, distances = {0: 0, 1: 1}.
Actual: distances = [0, -1], parent = [None, None] — vertex 1 was left unreachable.

## ROOT_CAUSE
In `insert_edge`, the distance-drop branch is guarded by `du + 1 < dv`:

```python
du, dv = dist[u], dist[v]
if du >= 0 and du + 1 < dv:
```

When `v` is currently unreachable, `dv = -1`, so the condition becomes `du + 1 < -1`, which is false for any reachable `u` (here `du = 0`, so `1 < -1` is false). The code therefore falls through to the `else` branch, which only does `rad[v] += 1` when `dv == du + 1` (also false, since `-1 != 1`). No distance or parent is ever assigned to `v`, so it stays at `dist = -1, parent = None`.

The guard was written for the "distance strictly decreases" case and silently assumes `dv >= 0`. The "v was unreachable and becomes reachable" case (`dv == -1`) is a distance drop from infinity and must be handled by the same subtree-reparenting path.

## REPAIR_HINTS
Change the branch condition in `insert_edge` to also fire when `v` is unreachable:

```python
if du >= 0 and (dv == -1 or du + 1 < dv):
```

The existing body already works for this case: `_subtree(adj, parent, v)` returns just `[v]` (v has no children since it was unreachable), `dist[v] = du + 1` and `parent[v] = u` are set, the inner BFS loop finds no further vertices, and `_rebuild_rad` over the affected set (v plus its out-neighbors) recomputes rad correctly.

Do NOT fix this by special-casing `dv == -1` with a separate code path that only sets `dist[v]`/`parent[v]` — that would miss the case where v's newly-reachable subtree (if v had stale children from a prior state) also needs re-parenting, and it would duplicate the rad-rebuild logic. The one-line condition change is the minimal correct fix.

Also verify the symmetric assumption in `delete_edge`: the `rad[v] -= 1` line is guarded by `dist[u] >= 0 and dist[v] == dist[u] + 1`, which is safe for unreachable v (the condition is false, no underflow), so no change needed there.
