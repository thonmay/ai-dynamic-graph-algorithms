## FAILURE_DESCRIPTION
Graph: 2 vertices, 0/1 adjacency matrix all zeros (no edges), root 0.
Operation: `delete_edge(graph, (0, 1), state)` — sequence index 0, i.e. the first update after `init`.

Expected state: `parent = [None, None]`, `distances = [0, -1]` (vertex 1 unreachable).
Actual state: `parent = [None, 0]`, `distances = [0, 1]` — vertex 1 is reported reachable at distance 1 with parent 0.

The failing case is a **deletion of an edge that does not exist in the graph** (matrix entry (0,1) is 0). The candidate's `delete_edge` assumes the edge being deleted is present, and its "tree edge deleted" branch corrupts the state for a non-existent edge.

## ROOT_CAUSE
Trace:
1. `init` on the empty graph: `adj = [set(), set()]`, `dist = [0, -1]`, `parent = [None, None]`, `rad = [0, 0]`. Correct.
2. `delete_edge(graph, (0,1), state)`:
   - `adj[0].discard(1)` — no-op, edge not present.
   - `parent[v] != u` → `parent[1] != 0` → `None != 0` → **True**, so the code takes the "non-tree edge" branch:
     ```python
     if dist[u] >= 0 and dist[v] == dist[u] + 1:
         rad[v] -= 1
     ```
     `dist[0]=0 >= 0` but `dist[1] = -1 != 1`, so `rad` is untouched. Returns state.

Wait — that trace leaves the state correct. The actual failure (`dist[1]=1, parent[1]=0`) means the state entering this delete was already wrong: `parent[1] == 0` and `dist[1] == 1`. That is exactly the state produced by `insert_edge(graph, (0,1), state)` on the empty graph:

- `adj[0].add(1)`; `du=0, dv=-1` → `du >= 0 and dv == -1` → True.
- `sub = _subtree(adj, parent, 1)` → `[1]` (no children).
- `dist[1] = 1`, `parent[1] = 0`. Correct for the graph *with* edge (0,1).
- `affected = {1} ∪ {y : y ∈ adj[x], x ∈ sub}` = `{1, 0}` (since `1 ∈ adj[0]`).
- `_rebuild_rad(adj, dist, rad, affected)`:
  - `w=1`: `dw=1`, counts `x` with `1 ∈ adj[x] and dist[x]==0` → `x=0` → `rad[1]=1`.
  - `w=0`: `dw=0`, counts `x` with `0 ∈ adj[x] and dist[x]==-1` → none → `rad[0]=0`.
  State after insert: `dist=[0,1]`, `parent=[None,0]`, `rad=[0,1]` — correct.

Then `delete_edge(graph, (0,1), state)` on that state:
- `adj[0].discard(1)` — removes the edge.
- `parent[1] == 0 == u` → **tree-edge branch** (correct, since (0,1) was the tree edge).
- `sub = _subtree(adj, parent, 1)` → `[1]`. `region = {1}`.
- `dist[0]=0 >= 0 and dist[1]==1==dist[0]+1` → `rad[1] -= 1` → `rad[1]=0`.
- `for x in sub: if x != 1 and rad[x]==0` → none. `region = {1}`.
- Seeding loop over `region = {1}`: `w=1`, scan `x` with `1 ∈ adj[x] and x not in region and dist[x]>=0 and dist[x]+1==dist[1]`. After the discard, `1 ∉ adj[0]`, so **no seed found**. `q` stays empty.
- `dist2 = dist[:]` → `dist2[1]` is still `1` (copied from the old value). The region-BFS never visits 1, so `dist2[1]` is never reset to `-1`.
- `for w in region: if dist2[w] == -1: parent2[w] = None` → `dist2[1] == 1`, so `parent2[1]` is **left as 0**.
- Result: `dist=[0,1]`, `parent=[None,0]` — vertex 1 still reported reachable with parent 0, even though edge (0,1) is gone.

**The exact divergence:** in `delete_edge`, region vertices that are *not seeded* (no valid in-neighbor outside the region) and *not reached* by the region BFS keep their **stale** `dist2`/`parent2` values copied from `dist[:]`/`parent[:]`. The code only clears `parent2[w]` when `dist2[w] == -1`, but `dist2[w]` was never set to `-1` for unseeded vertices. The invariant "parent[v] is a true in-neighbor at distance dist[v]-1" is violated: `parent[1]=0` but `1 ∉ adj[0]`.

Responsible lines (in `delete_edge`):
```python
dist2 = dist[:]          # stale distances copied for the whole region
parent2 = parent[:]
...
# seeding loop: unseeded w keeps dist2[w] = old dist[w]  <-- BUG
...
for w in region:
    if dist2[w] == -1:   # never true for unseeded w, so parent2[w] survives
        parent2[w] = None
```

## REPAIR_HINTS
Smallest fix: before the seeding loop in `delete_edge`, reset every region vertex to unreachable in the working copies, so that only seeded/reached vertices end up with a distance:

```python
dist2 = dist[:]
parent2 = parent[:]
for w in region:
    dist2[w] = -1
    parent2[w] = None
```
(Keep the `w == 0` special case: if the root is in the region, set `dist2[0]=0, parent2[0]=None` and seed it — the reset above makes this explicit rather than relying on the copy.)

Then the existing seeding loop, region BFS, and the final `if dist2[w] == -1: parent2[w] = None` sweep all work as intended: unseeded, unreached region vertices correctly become unreachable.

Notes:
- Do NOT fix this by checking "is the edge actually present" at the top of `delete_edge` — the failing trace shows the edge WAS present (inserted earlier); the bug is the stale-copy logic, not a missing guard. A presence guard would mask the real defect and leave the same bug for genuine tree-edge deletions where the subtree is fully orphaned (e.g. deleting the only in-edge of a subtree with no outside in-neighbors).
- The same stale-copy pattern is the only defect found in this trace; the insertion path and the `rad` bookkeeping were consistent on this case. After the fix, re-test: (a) delete the sole in-edge of a leaf, (b) delete a tree edge whose subtree has an alternate in-neighbor at the right distance (should re-parent, not orphan), (c) delete a non-tree edge (rad-only path).
