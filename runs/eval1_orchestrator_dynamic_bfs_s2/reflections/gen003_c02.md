## FAILURE_DESCRIPTION
Graph (4 vertices, root 0), operation `delete (0, 2)`. The graph shown is the state AFTER the deletion; before it, `graph[0][2] = 1` (edge 0→2 existed and was the BFS tree edge into vertex 2, so `parent[2] = 0`, `dist[2] = 1`).

- Expected after deletion: `distances = {0:0, 3:1, 1:2, 2:2}`, `parent = {0:None, 3:0, 1:3, 2:3}` (vertex 2 is still reachable at distance 2 via 3→2).
- Actual: `parent = [None, 3, 1, 0]`, i.e. `parent[2] = 1`, `dist[2] = 3`.
- Violated property: vertex 2's maintained distance (3) is not its true BFS distance (2); its parent 1 sits at distance 2, so the "parent is one level closer" invariant is broken.

## ROOT_CAUSE
In `delete_edge`, when the deleted edge is a tree edge, the cut subtree is re-discovered by a "BFS seeded with all still-reachable vertices":

```python
q = deque(w for w in range(n) if w not in in_sub and dist[w] != -1)
while q:
    x = q.popleft()
    dx = dist[x]
    for y in adj[x]:
        if y in in_sub and dist[y] == -1:
            dist[y] = dx + 1
            parent[y] = x
            children[x].add(y)
            q.append(y)
```

The seed is built in **vertex-id order, not distance order**. A multi-source BFS is only a true BFS (and only yields shortest distances) if the initial queue is non-decreasing in distance. Here the seed for this case is `[0 (d0), 1 (d2), 3 (d1)]`. Processing in that order:
1. `x=0` (d0): adj[0]={3}; 3 not cut.
2. `x=1` (d2): adj[1]={2}; 2 is cut and `dist[2]==-1` → sets `dist[2]=3`, `parent[2]=1`.
3. `x=3` (d1): adj[3]={1,2}; 2 is cut but `dist[2]==3 != -1`, so it is **not** re-assigned to the shorter distance 2.

Result: `dist[2]=3`, `parent[2]=1` — exactly the observed wrong output. The `dist[y] == -1` guard makes the first (non-minimal) discovery sticky, so the out-of-order seed corrupts the distance.

## REPAIR_HINTS
Make the re-discovery a genuine BFS so the first discovery is the shortest. Smallest concrete change: seed the queue in non-decreasing distance order. Replace

```python
q = deque(w for w in range(n) if w not in in_sub and dist[w] != -1)
```

with

```python
q = deque(sorted((w for w in range(n) if w not in in_sub and dist[w] != -1),
                 key=lambda w: dist[w]))
```

Because every newly enqueued cut vertex gets `dist = parent_dist + 1`, a distance-sorted seed keeps the whole queue non-decreasing in distance, so the first time a cut vertex is popped/discovered it is at its true minimum distance and the `dist[y] == -1` guard is then correct.

Alternative that also works: allow re-relaxation — when `y in in_sub` and `dx + 1 < dist[y]`, update `dist[y]`, `parent[y]`, `children` and re-enqueue (a proper Dijkstra/BFS relaxation). This is more code; the sorted-seed fix is the minimal one.

Approaches that will NOT work:
- Keeping the vertex-id-ordered seed and only fixing the radius pass — the distance/parent corruption happens before radii are touched.
- Re-seeding only the direct neighbors of `u` — the cut region can be reached from many non-cut vertices, so a local seed misses the true shortest in-edge.
- Note the `insert_edge` path is not implicated here; do not "fix" it based on this case. (A full recompute via `_bfs_full` after every deletion is correct but defeats the research goal of avoiding full recomputation; prefer the sorted-seed fix.)
