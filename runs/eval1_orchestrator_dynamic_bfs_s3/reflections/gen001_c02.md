## FAILURE_DESCRIPTION

Case: n=2, root 0. The harness starts from the EMPTY graph (all-zero 2x2 matrix) and applies the update sequence; at `sequence_idx: 0` the operation is `insert (0, 1)`. The `graph` field in the case record is the graph AFTER the update (row 0 = [0,1]).

Expected after the insert: `parent = {0: None, 1: 0}`, `distances = {0: 0, 1: 1}`.
Actual returned: `distances = [0, -1]`, `parent = [None, None]` (vertex 1 reported unreachable).

## ROOT_CAUSE

The candidate's `insert_edge` only handles distance *decreases*; it has no branch for a vertex going from unreachable (-1) to reachable.

Trace: `init` on the empty graph gives `dist = [0, -1]`, `parent = [None, None]`, `rad = [0, 0]`. Then `insert_edge(graph, (0,1), state)`:

1. `adj[0].add(1)` — adjacency is updated correctly.
2. `rad[v] += 1` — `rad[1]` becomes 1 (inconsistent with dist[1] = -1, but not the direct cause).
3. `du = dist[0] = 0` (not < 0, so no early return).
4. The guard `if dist[v] <= du + 1:` evaluates `dist[1] = -1 <= 1` → **True**, so the function returns immediately with the stale `dist[1] = -1` and `parent[1] = None`.

The guard's comment ("v's distance does not decrease; no vertex can be improved") is only valid when `dist[v] >= 0`. For an unreachable head, `dist[v] = -1 <= du + 1` is always true, so the code silently treats "first becomes reachable" as "no change". The propagation BFS below the guard is the only code path that ever assigns a finite distance/parent on insertion, and it is never reached in this case.

## REPAIR_HINTS

In `insert_edge`, before the `if dist[v] <= du + 1:` guard, add an explicit branch for the unreachable-head case:

```python
if dist[v] == -1:
    # v becomes reachable at du+1; propagate to newly reachable vertices.
    improved = {v}
    newdist = {v: du + 1}
    newparent = {v: u}
    queue = [v]; head = 0
    while head < len(queue):
        x = queue[head]; head += 1
        dx = newdist[x]
        for y in adj[x]:
            if dist[y] == -1 and y not in improved:
                improved.add(y)
                newdist[y] = dx + 1
                newparent[y] = x
                queue.append(y)
    for x in improved:
        dist[x] = newdist[x]
        parent[x] = newparent[x]
    # recompute rad for improved vertices (same scan as the existing code)
    for x in improved:
        dx = newdist[x]
        c = 0
        for a in range(n):
            if dist[a] == dx - 1 and x in adj[a]:
                c += 1
        rad[x] = c
    return state
```

Notes:
- The existing propagation loop's condition `dist[y] > dx + 1` would actually also accept `dist[y] == -1` (since -1 > dx+1 is False... wait, -1 > 1 is False, so it would NOT accept it) — so the existing loop cannot be reused as-is for the -1 case; the new branch must test `dist[y] == -1` (or `dist[y] < 0`) explicitly. Do not just remove the guard; the guard is correct for reachable v.
- The `rad[v] += 1` at the top of `insert_edge` is also wrong when `dist[v] == -1` (rad is only meaningful for reachable vertices), but it is harmless for correctness of parent/distances; the rad recompute in the new branch overwrites it. For consistency, consider skipping the `rad[v] += 1` when `dist[v] == -1` (or recomputing rad[v] in the new branch, which the snippet does).
- The same "unreachable head" gap likely exists in `delete_edge`'s symmetric reasoning (a vertex becoming unreachable), but the failing case is the insertion; fix the insertion first and re-test deletions that disconnect vertices.
