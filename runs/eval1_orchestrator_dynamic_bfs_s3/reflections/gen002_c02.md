## FAILURE_DESCRIPTION

3-vertex directed graph (0/1 adjacency matrix), root 0:

```
graph = [[0,0,0],
         [1,0,1],
         [0,0,0]]
```

Edges: 1->0 and 1->2. Only vertex 0 (the root) is reachable; vertices 1 and 2 are unreachable.

Failing update (sequence_idx 0): `delete_edge(graph, (0, 1), state)` — delete edge 0->1.

Expected after the update: `distances = [0, -1, -1]`, `parent = [None, None, None]` (vertex 2 unreachable, expected_distance -1).

Actual: `distances = [0, -1, 2]`, `parent = [None, None, 1]` — vertex 2 is reported reachable at distance 2 with parent 1, even though 1 is unreachable and no path from 0 reaches 2.

## ROOT_CAUSE

The bug is in `delete_edge`, in the `best_p is None` branch (the "v becomes unreachable" path):

```python
if best_p is None:
    # v and its whole old subtree may be affected; BFS from v with
    # v marked unreachable (dist -1) so it is not re-added.
    distances[v] = -1
    parent[v] = None
    new_dist, new_parent = _bfs_from(v, adj, distances, parent,
                                     start_dist=-1, start_parent=None)
    _apply_patch(state, new_dist, new_parent)
```

When `start_dist == -1`, `_bfs_from` does:

```python
queue = [start] if start_dist != -1 else []   # queue = []  <-- empty
...
while head < len(queue):                       # never executes
```

So the BFS body never runs, `new_dist`/`new_parent` stay empty, and `_apply_patch` patches nothing. The only state change is `distances[v] = -1; parent[v] = None` for the head `v` itself.

The comment says "v and its whole old subtree may be affected", but the code only marks `v`. Every tree descendant of `v` (vertices whose only path from the root went through `v`) keeps its stale distance and parent. In the failing case, the pre-deletion state (with edge 0->1 present) had `dist = [0, 1, 2]`, `parent = [None, 0, 1]` — vertex 2's tree parent is 1. After deleting 0->1, `best_p` is None (1's only in-neighbor is 0, and 0 has no edge to 1), so the branch sets `dist[1] = -1, parent[1] = None`, but vertex 2 is left at `dist[2] = 2, parent[2] = 1` — a parent that is itself unreachable. The invariant "parent[v] is a true in-neighbor at distance dist[v]-1" is violated.

Note the dead helper `_mark_unreachable(v, adj, dist, parent)` exists in the file and does exactly the intended subtree walk (follows `parent[w] == u` edges, marks dist -1 / parent None), but `delete_edge` never calls it — the author replaced it with the `start_dist=-1` call to `_bfs_from`, which is a no-op.

## REPAIR_HINTS

Smallest fix, in `delete_edge`'s `best_p is None` branch: after setting `distances[v] = -1; parent[v] = None`, walk v's old BFS-tree subtree and mark every descendant unreachable. The existing (currently unused) `_mark_unreachable` helper does this correctly:

```python
if best_p is None:
    new_dist, new_parent = _mark_unreachable(v, adj, distances, parent)
    _apply_patch(state, new_dist, new_parent)
```

(`_mark_unreachable` starts with `{v: -1}` and follows `parent[w] == u` edges, so it covers v and exactly the vertices whose only tree path went through v.)

Two caveats to verify after the fix:

1. `_mark_unreachable` only marks vertices whose tree parent is the vertex being processed. A descendant w whose parent is NOT in the marked set is skipped ("it may still be reachable via that parent"). That is correct for the BFS-tree structure: if w's parent p is not a descendant of v, then w's path to the root does not go through v, so w is unaffected. Keep this logic.

2. The `best_p is not None` branch (v gets a new parent at `best_d + 1`) has a related latent issue: `_bfs_from(v, ...)` with the updated `distances[v] = best_d + 1` only propagates to vertices whose old distance is `> du + 1` (the skip `dist[w] <= du + 1`). If v's new distance is LARGER than its old one (the replacement parent is farther), descendants whose old distance is smaller than the new value are skipped and keep stale, too-small distances. This case does not trigger in the failing test, but the repair role should either (a) restrict that branch to `best_d + 1 == old dist[v]` (same-level re-parenting, where the skip logic is sound) and fall back to a full BFS when `best_d + 1 > old dist[v]`, or (b) recompute the whole subtree of v with a multi-source BFS seeded from in-neighbors outside the subtree (as gen002_c01/c04 do). Do not "fix" the unreachable branch by making `_bfs_from` enqueue `start` when `start_dist == -1` — that would re-add v as reachable, the opposite of what is needed.
