## FAILURE_DESCRIPTION
Crash (TypeError) on the very first operation of the sequence (sequence_idx 0, n=2):
`TypeError: '>=' not supported between instances of 'int' and 'NoneType'` at
`delete_edge`, line 262:

```python
affected = set()
for w in range(n):
    if dist[w] == -1 or dist[w] >= new_d:
        affected.add(w)
```

The failing case is a deletion of a tree edge (u, v) for which `_find_new_parent`
returned `new_d = None` (v has no unaffected in-neighbor, so v becomes
unreachable). The code then falls through to the `affected`-set loop, where
`dist[w] >= new_d` compares an int against `None`. The `if new_d is None:`
branch that handles the unreachable case exists, but it is placed AFTER the
affected-set computation, so the crash happens before it is ever reached.

## ROOT_CAUSE
In `delete_edge`, the affected-set loop is executed unconditionally, before the
`new_d is None` check. When `new_d` is `None`, the comparison `dist[w] >= new_d`
raises TypeError. The unreachable branch (`if new_d is None: for w in affected:
dist[w] = -1; parent[w] = None`) is dead code in that case because the crash
precedes it.

Note the contrast with `insert_edge`, where the analogous threshold `new_dv =
dist[u] + 1` is always an int (guarded by `dist[u] != -1`), so the same loop
pattern is safe there.

## REPAIR_HINTS
Smallest fix: move the affected-set computation inside the `else` branch (i.e.
only compute `affected` when `new_d is not None`), or guard the loop with
`if new_d is not None and (dist[w] == -1 or dist[w] >= new_d)`. In the
`new_d is None` branch, the affected set is simply "v's subtree" (the subtree
rooted at v in the current BFS tree) — compute it with `_subtree(adj, n, parent,
v)` and set dist/parent to -1/None for exactly those vertices. Do NOT use the
`dist[w] == -1 or dist[w] >= new_d` heuristic in the None branch: it would mark
every currently-unreachable vertex as affected (harmless for dist, but it would
also wipe parent of vertices that were already unreachable — still fine — but it
is conceptually wrong and unnecessary).

Approaches that will not work:
- Comparing with a sentinel like `new_d if new_d is not None else -1`: when
  `new_d` is None, `dist[w] >= -1` is true for every reachable vertex, so the
  affected set becomes the whole reachable set and the detach loop would
  incorrectly mark reachable vertices (outside v's subtree) as unreachable.
- Simply swapping the order (check `new_d is None` first, then compute
  affected) without changing what the None branch iterates over: the None
  branch currently iterates `for w in affected`, so affected must still be
  defined; it must be defined as v's subtree, not the distance-threshold set.
