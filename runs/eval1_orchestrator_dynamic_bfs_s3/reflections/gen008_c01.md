## FAILURE_DESCRIPTION

Graph (3x3, directed): only edge is (1,0). Root = 0.
- After `init`: dist = [0, -1, -1], parent = [None, None, None]. Correct.
- Operation 0: `delete_edge(graph, (0,1), state)` — deleting edge (0,1), which is NOT present in the graph (graph[0][1] == 0).
- Expected: dist = [0, -1, -1], parent = [None, None, None] (no-op; verifier pins vertex 0: dist 0, parent None).
- Actual: dist = [-1, -1, -1], parent = [None, None, None]. Vertex 0's distance is -1 instead of 0.

## ROOT_CAUSE

`delete_edge` has no guard for deleting an edge that is not present in the graph. The code unconditionally does:

```python
adj[u].discard(v)
in_adj[v].discard(u)
```

then checks `if parent[v] != u: return`. For edge (0,1): u=0, v=1, `parent[1]` is None, `None != 0` is True, so it returns early. On the surface this looks like a no-op, but the reported result shows dist[0] = -1, which can ONLY be produced by `_recompute_region`'s apply loop:

```python
for v in range(n):
    if dist[v] != -1 and dist[v] < min_sd:
        continue  # unaffected
    if v in new_dist:
        dist[v] = new_dist[v]
        parent[v] = new_parent[v]
    else:
        dist[v] = -1
        parent[v] = None
```

This means `_recompute_region` WAS called, which means `parent[v] == u` was True, which means `parent[1] == 0`. This is only possible if the state was already corrupted before this delete call (e.g., a prior operation set parent[1] = 0 incorrectly), OR the test harness's "delete (0,1)" is actually operating on a state where edge (0,1) WAS present.

Given the graph shown has only edge (1,0), the most likely explanation is: **the test harness is deleting edge (0,1) from a state where the graph previously had edge (0,1)** (the "graph" field in the failing case may represent the graph AFTER the deletion, not before). If the graph before deletion had edges (0,1) and (1,0), then:
- init: dist = [0, 1, -1], parent = [None, 0, None]
- delete (0,1): u=0, v=1, `parent[1] == 0 == u` → tree edge deleted
- `old_dv = dist[1] = 1`
- `in_adj[1]` after discard: empty (only in-neighbor was 0)
- `best = -1`, `best_p = None`
- `dist[1] = -1`, `parent[1] = None`
- Since `best == -1`, enters the else branch:
  ```python
  seeds = [w for w in range(n) if w != v and (dist[w] == -1 or dist[w] >= old_dv)]
  ```
  old_dv = 1. dist = [0, -1, -1]. Seeds: w=0: dist[0]=0, 0 >= 1? No. dist[0] != -1? Yes, but 0 >= 1 is False. So w=0 is NOT a seed. w=2: dist[2]=-1, so w=2 IS a seed. seeds = [2].
- `_recompute_region(adj, in_adj, 3, parent, dist, [2])`:
  - `min_sd = min(dist[2]) = min(-1) = -1`
  - Seed 2: new_dist[2] = -1, new_parent[2] = None
  - "Add affected vertices with unaffected in-neighbor" loop: for v=0: dist[0]=0, 0 < -1? No (0 is not < -1). So v=0 is "affected". Check in_adj[0] = {1}. dist[1] = -1, so no unaffected in-neighbor. v=0 NOT added to new_dist.
  - BFS relaxation: pop 2, du = -1. adj[2] is empty. Nothing propagates.
  - Apply loop: v=0: dist[0]=0, 0 < -1? No. v=0 not in new_dist → **dist[0] = -1, parent[0] = None**. BUG!

The root cause is that `_recompute_region` with `min_sd = -1` treats ALL vertices as "affected" (since no dist is < -1), and vertex 0 (the root) is not in `new_dist`, so it gets wiped to -1. The root should NEVER be subject to recomputation — it is always at distance 0 with parent None.

## REPAIR_HINTS

1. **Primary fix — protect the root in `_recompute_region`**: In the apply loop, skip vertex 0 unconditionally:
   ```python
   for v in range(n):
       if v == 0:
           continue  # root is always dist 0, parent None
       if dist[v] != -1 and dist[v] < min_sd:
           continue
       ...
   ```
   Also skip vertex 0 in the "add affected vertices" loop and the BFS relaxation (never relax INTO vertex 0, never use it as a seed).

2. **Secondary fix — guard against deleting non-existent edges**: At the top of `delete_edge`, after the discard calls, check if the edge was actually present:
   ```python
   if v not in adj[u]:
       return {'parent': parent, 'distances': dist, 'adj': adj, 'in_adj': in_adj, 'n': n}
   ```
   This prevents any state corruption from no-op deletes.

3. **Tertiary fix — the `best == -1` seed computation**: When `old_dv = -1` (v was already unreachable), the condition `dist[w] >= old_dv` becomes `dist[w] >= -1` which is true for ALL vertices. This is overly broad. When v was unreachable, deleting its tree edge (which shouldn't exist if v is unreachable) is a no-op. Add a guard: if `old_dv == -1`, return early (v was unreachable, so it had no valid tree edge).

4. **Approach that will NOT work**: Simply checking `if v == 0: return` at the top of `delete_edge` (as the current code does for the head-is-root case) does NOT protect against the root being wiped by `_recompute_region` when the root is a vertex OTHER than the deleted edge's head. The root must be protected inside `_recompute_region` itself.
