## FAILURE_DESCRIPTION
Graph: 2x2 all-zero adjacency matrix (n=2, no edges). `init` yields a valid
state: only vertex 0 (the root) is reachable — parent=[None, None],
disc=[0, None], fin=[1, None], order=[0], counter=2.

Update: `insert_edge(graph, (0,1), state)` (matrix now has edge 0->1).

Expected (any valid DFS order): parent=[None, 0], discover=[0, 1],
finish=[3, 2] — i.e. vertex 1 discovered at time 1, finished at 2, root
finished at 3.

Actual returned: parent=[None, 0], discover=[0, 2], finish=[1, 3].

Violated property: the verifier requires discover/finish to be produced by ONE
shared counter (root discover 0, next event 1, ...). Here the root's finish
time (1) is SMALLER than the child's discover time (2), which is impossible
for a single shared counter: a vertex's finish must come after all of its
descendants' discover/finish events. The child's interval [2,3] is not nested
inside the root's interval [0,1].

## ROOT_CAUSE
In `insert_edge`, the "v unreachable" branch appends the newly reachable
vertices AFTER the old numbering instead of inside the source's open DFS
frame:

```python
    # v unreachable: it and everything reachable from v become reachable.
    # Re-search from v, continuing the numbering after the old counter.
    parent[v] = u
    disc[v] = counter
    counter += 1
    order, counter = _dfs_from(v, adj, n, parent, disc, fin, order, counter)
```

`counter` here is the old global counter (2), which is already past the
finish time of every previously reachable vertex — including the source u=0
(fin[0]=1). So v gets disc=2 and its subtree gets times 2..3, while u keeps
fin=1. The new vertices are numbered as if they were discovered in a NEW
search phase after the old search fully finished, rather than as a
continuation of u's still-open DFS frame. This breaks the nesting invariant
disc[u] < disc[v] < fin[v] < fin[u] for the new tree edge u->v.

Traced concretely: old state disc=[0,None], fin=[1,None], counter=2.
Insert 0->1: disc[1]=2, counter=3; _dfs_from(1,...) finds no unvisited
neighbors, sets fin[1]=3, counter=4. Result disc=[0,2], fin=[1,3] — exactly
the failing output.

Note the same latent bug exists in `delete_edge`: after re-searching from u,
u's ancestors (and u itself) get NEW finish times, but the prefix vertices
keep their OLD finish times, so an ancestor's old finish can end up smaller
than a renumbered descendant's times (e.g. delete 0->1 from graph 0->1, 1->2
gives fin[0]=1 but disc[2]=2). It did not fire in this case but will in
deeper graphs.

## REPAIR_HINTS
Smallest fix for the failing case (insert_edge, "v unreachable" branch):
do NOT continue numbering after the old counter. Instead, re-open the source
u's DFS frame:

1. Find u's position in `order`; prefix = order[:pos_u] (vertices whose
   intervals are fully closed and keep their old numbers).
2. Clear disc/fin/parent for every vertex in order[pos_u:] (u, its
   descendants, and the old tail).
3. Set counter = max(fin[w] for w in prefix, default=0).
4. Restore parent[u] (u_parent), set disc[u] = counter, counter += 1,
   order = list(prefix), then `order, counter = _dfs_from(u, adj, n, parent,
   disc, fin, order, counter)`.

This is exactly the re-search pattern `delete_edge` already uses, and it
guarantees the new vertices are numbered inside u's (and its ancestors')
intervals, so fin[u] > fin[v] holds. For the failing case this yields
disc=[0,1], fin=[3,2].

The same re-open-from-u pattern must also be applied in `delete_edge` (it
already re-searches from u, but it must clear and renumber u's ANCESTORS'
finish times too — i.e. reset from the earliest ancestor whose interval
contains v, not just from u — otherwise the prefix's stale finish times
break nesting for deeper trees).

Approaches that will NOT work:
- Keeping the "continue after old counter" numbering and only patching the
  returned dict: the counter is shared, so any append-after-old-counter
  scheme violates nesting for the source's ancestors.
- Special-casing the 2-vertex case: the bug is structural (numbering
  outside the source's open frame) and appears in every insert of an edge
  to an unreachable vertex, and in delete_edge for depth >= 2.
