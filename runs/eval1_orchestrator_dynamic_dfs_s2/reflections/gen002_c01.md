## FAILURE_DESCRIPTION
Graph: 2 vertices, initially empty (graph_shape [[0,0],[0,0]]). Operation at sequence_idx 0: `insert (0, 1)`.
- Expected after the insert: `parent = {0: None, 1: 0}`, `discover = {0: 0, 1: 1}`, `finish = {1: 2, 0: 3}` (vertex 1 is reachable from root 0 via the new tree edge 0->1).
- Actual returned state: `parent = [None, None]`, `discover = [0, -1]`, `finish = [1, -1]` (vertex 1 still marked unreachable).
The verifier checks reachability/parent for every vertex reachable from the root, so vertex 1 with `parent[1] = None` and `discover[1] = -1` fails the check.

## ROOT_CAUSE
`insert_edge` only handles the forward-cross case; it never handles the case where the inserted edge makes a previously UNREACHABLE vertex reachable.

Trace: `init` on the empty graph runs `_dfs_full`, which starts a DFS from every unvisited vertex (the `for s in range(n)` loop), so it returns `disc = [0, 2]`, `fin = [1, 3]` — vertex 1 gets a *spurious* discovery/finish time from its own root, not -1. Then `insert_edge(0,1)`:
- `disc[0] = 0`, `disc[1] = 2`, so `disc[u] < disc[v]` is True;
- `_is_ancestor(disc, fin, 0, 1)` checks `disc[0] <= disc[1] and fin[1] <= fin[0]` → `0 <= 2 and 3 <= 1` → False;
- so the condition `disc[u] < disc[v] and not _is_ancestor(...)` is True and `_recompute` is called.

`_recompute` calls `_dfs_full(graph)` on the now-non-empty graph, which correctly yields `parent = [None, 0]`, `disc = [0, 1]`, `fin = [2, 3]`. So the recompute path itself is fine — the bug is that the state *before* the recompute (and the state after any insert that does NOT trigger a recompute) is already wrong: `_dfs_full`'s multi-source loop assigns discovery/finish times to vertices unreachable from root 0, violating the state contract that unreachable vertices must have `discover/finish = -1` and `parent = None`.

Two concrete defects, both in the same family:
1. `_dfs_full` (lines: `for s in range(n): if disc[s] == -1: rec(s)`) performs a full forest DFS over ALL vertices, not just from root 0. After `init` on a graph where some vertices are unreachable from 0, `state['discover']`/`state['finish']` contain non-(-1) values for unreachable vertices. This alone would fail any verifier check on the initial state, and it corrupts the `disc[u] < disc[v]` / `_is_ancestor` tests in `insert_edge` (e.g., an insert of a back edge 1->0 on the empty graph would see `disc[1]=2 > disc[0]=0` and skip the recompute, leaving vertex 1 wrongly marked reachable).
2. `insert_edge`'s trigger condition `disc[u] < disc[v] and not _is_ancestor(disc, fin, u, v)` misses the case `disc[v] == -1` (v was unreachable, now reachable via u). With a correct single-root DFS, inserting u->v with v unreachable must always recompute (or re-search from v), but `disc[u] < -1` is False, so the code returns the stale state unchanged.

In this specific failing case the recompute *was* triggered (by accident, via the spurious disc[1]=2), so the final divergence is defect 1's corrupted pre-state combined with the verifier's expectation that the returned state after the update is a valid single-root DFS — the actual output `[0, -1]`/`[1, -1]` shows the harness observed the state as if no recompute happened, i.e., the state contract (unreachable = -1) was never satisfied by the code's own bookkeeping.

## REPAIR_HINTS
Smallest concrete changes:
1. Make `_dfs_full` a single-root DFS from vertex 0 only: remove the `for s in range(n)` outer loop (or replace it with `rec(0)` guarded by `disc[0] == -1`). Unreachable vertices then correctly keep `disc = fin = -1`, `parent = None`. This fixes both the initial-state contract and the corrupted `disc`/`fin` values used by `insert_edge`'s tests.
2. In `insert_edge`, add the reachability case: after `state['adj'][u].add(v)`, recompute (or re-search) if `disc[v] == -1 and disc[u] != -1` (new edge makes v reachable). Keep the existing forward-cross test for the reachable case. Note that with fix 1, the forward-cross test `disc[u] < disc[v] and not _is_ancestor(...)` is safe because unreachable vertices have `disc = -1` and are excluded by the `disc[u] < disc[v]` guard only when u is also unreachable — handle `disc[u] == -1` explicitly (no reachable source can make anything reachable, so skip).
3. `_reattach` already does a correct single-root DFS from 0 over `state['adj']` (unreachable → -1), so it is consistent with fix 1; no change needed there.

Approaches that will NOT work:
- Keeping the multi-source `_dfs_full` and "fixing" `insert_edge` to special-case `disc[v] != -1` for unreachable vertices: the initial state itself would still violate the contract (unreachable vertices with non-(-1) times), and the forward-cross test remains unreliable because spurious disc/fin values from other DFS roots break the ancestor test.
- Only patching the failing case (e.g., special-casing n=2 or the first insert): the same defect triggers on any graph where init leaves vertices unreachable from 0, and on any later insert of an edge into an unreachable vertex.
