## FAILURE_DESCRIPTION

Failing case: n=2, sequence index 0, operation "crash". The candidate raised
`ValueError: 1 is not in list` at line 175 of `delete_edge`:

```python
pos = order.index(v)
```

with `v = 1`. The guard `if parent[v] != u: return` at line 169 passed,
meaning `parent[1] == u` for some `u`, but vertex 1 was not present in the
`order` list. The `parent` array and the `order` list were out of sync.

## ROOT_CAUSE

The state corruption originates in `insert_edge`, in the branch handling the
case where `v` is unreachable AND `u` is also unreachable (lines 127–131):

```python
if disc[u] is None:
    # u was unreachable too: the whole component is new.
    parent[u] = None
    disc[u] = counter
    counter += 1
    order, counter = _dfs_from(u, adj, n, parent, disc, fin, order, counter)
    return _state_fields(state)
```

This branch is **wrong for a fixed-root DFS forest**. If `u` is not
reachable from root 0, then inserting edge `u->v` cannot make `v` reachable
from root 0 either (there is no path from 0 to `u`, so no path from 0 to `v`
through `u`). The correct behavior is a **no-op**: the DFS forest from root
0 is unchanged.

Instead, the code makes `u` a new root (`parent[u] = None`) and runs a DFS
from `u`, adding `u` and all its descendants to `order` with valid
`disc`/`fin`/`parent` values. This corrupts the state: vertices that are
NOT reachable from root 0 get marked as reachable in `disc`/`fin`/`parent`
and added to `order`.

**How the corruption leads to the crash:**

The corruption creates a state where `disc[v]` is non-None for a vertex `v`
that is not actually reachable from root 0. This has two downstream effects:

1. **False early return in `insert_edge`**: If a later insert makes `v`
   actually reachable from root 0, the check `if disc[v] is not None: return`
   (line 121) fires incorrectly, skipping the necessary forest update. The
   forest is now missing a vertex that should be in it.

2. **Stale `parent` values survive `order` rebuilds**: In both
   `insert_edge` and `delete_edge`, the reset loop only clears vertices in
   the **current** `order`:
   ```python
   for w in order[pos_u:]:
       parent[w] = None
       disc[w] = None
       fin[w] = None
   ```
   If a vertex was added to `order` by the buggy branch but is later excluded
   from the rebuilt `order` (because the new `prefix` doesn't include it),
   its `parent`/`disc`/`fin` are not cleared. This creates the exact
   inconsistency that triggers the crash: `parent[1] == u` (non-None) but
   `1 not in order`.

**Concrete trace for n=2 (one possible sequence):**

1. **Init** with graph `[[0,0],[0,0]]` (no edges).
   State: `parent=[None,None]`, `disc=[0,None]`, `fin=[1,None]`,
   `order=[0]`, `counter=2`.

2. **Insert (1, 1)**: `disc[1] is None`, `disc[1] is None` → enters the
   buggy branch.
   - `parent[1]=None, disc[1]=2, counter=3`.
   - `_dfs_from(1, ...)`: adj[1]=[1]. disc[1] not None (just set). Pop 1:
     `fin[1]=3, counter=4`.
   - State: `parent=[None,None]`, `disc=[0,2]`, `fin=[1,3]`, `order=[0,1]`,
     `counter=4`.
   - **CORRUPTION**: vertex 1 is in `order` with `disc[1]=2`, but it is NOT
     reachable from root 0. `parent[1]=None` makes it look like a second
     root.

3. **Insert (0, 1)**: `disc[1] is not None` (it's 2, from the corruption) →
   early return. **BUG**: vertex 1 is now actually reachable from root 0
   (edge 0->1 was just added), but the code thinks it's already reachable
   and does nothing. The forest is missing vertex 1.

4. **Delete (0, 1)**: `parent[1] == None != 0` → early return. No change.
   (The code thinks 1 is not a tree child of 0, so it does nothing. But 1
   IS reachable from 0 via this edge. The forest is wrong.)

This trace shows incorrect results but not the crash. The crash requires
`parent[1]` to be a **non-None** value while `1 not in order`. This can
happen if:

- A vertex is added to `order` with a non-None `parent` by `_dfs_from`
  (called from the buggy branch or a legitimate update).
- A subsequent operation rebuilds `order` from a `prefix` that excludes this
  vertex, but the reset loop doesn't clear its `parent` because the vertex
  is not in the current `order` at the time of the reset.

The exact sequence depends on the specific graph and update order, but the
root cause is always the same: the `disc[u] is None` branch in
`insert_edge` corrupts the state by adding unreachable vertices to the
forest.

## REPAIR_HINTS

1. **Fix the `disc[u] is None` branch in `insert_edge` (lines 127–131)**:
   If `u` is not reachable from root 0, inserting `u->v` does NOT make `v`
   reachable from root 0. This branch should be a **no-op**:
   ```python
   if disc[u] is None:
       # u is not reachable from root 0, so v cannot become reachable.
       return _state_fields(state)
   ```
   Remove the code that makes `u` a new root and searches from it. The
   fixed-root DFS forest only includes vertices reachable from vertex 0.

2. **The `disc[v] is not None` early return in `insert_edge` (line 121) is
   fragile**: if the state is corrupted (e.g., `disc[v]` is set but `v` is
   not actually reachable from root 0), this early return will skip a
   necessary update. After fixing #1, this should be safe, but consider
   adding an assertion or a consistency check.

3. **Add a defensive consistency check in `delete_edge` before
   `order.index(v)`**:
   ```python
   if v not in order:
       # State inconsistency: parent[v] == u but v not in order.
       # Fall back to a full re-search.
       parent, disc, fin, order, counter = _full_search(adj, n)
       return _state_fields({'parent': parent, 'disc': disc, 'fin': fin,
                             'order': order, 'counter': counter, 'adj': adj})
   ```
   This is a band-aid, not a fix. The real fix is #1.

4. **Do NOT** try to fix this by only changing the `order.index` call to a
   try/except. The underlying state corruption will cause incorrect results
   even if the crash is avoided.

5. **Consider adding a consistency check after every update** (at least in
   debug mode): verify that for all `v`, `disc[v] is not None` iff `v in
   order`, and `parent[v] is not None` implies `disc[v] is not None`. This
   would catch corruption early.
