## FAILURE_DESCRIPTION
Case: n=2, initial graph is the empty 2x2 matrix (no edges). After `init`,
state is parent=[None,None], discover=[0,-1], finish=[1,-1] (vertex 0 is the
only reachable vertex; vertex 1 is unreachable, discover=-1).

Operation: `insert_edge(graph, (0,1), state)`. The graph now has edge 0->1,
so vertex 1 is reachable from root 0.

Expected: parent[1]=0, discover[0]=0, discover[1]=1, finish[1]=2, finish[0]=3
(vertex 1 must be in the DFS tree).
Actual: state returned unchanged: parent=[None,None], discover=[0,-1],
finish=[1,-1]. Vertex 1 is still reported unreachable even though 0->1 exists.

## ROOT_CAUSE
In `insert_edge`, the only condition that triggers a recompute is:

```python
if disc[u] < disc[v] and not _is_ancestor(disc, fin, u, v):
    return _recompute(graph, state)
```

This condition only detects *forward-cross* edges among already-reachable
vertices. It completely misses the case where the new edge makes a previously
**unreachable** vertex reachable. Here u=0, v=1: `disc[0]=0`, `disc[1]=-1`,
so `disc[u] < disc[v]` is `0 < -1` = False, and the function returns the
state unchanged. The new edge 0->1 is a tree edge to a newly reachable
vertex, but no recompute is triggered, so discover/finish/parent for vertex 1
are never updated.

The same class of bug exists in the reverse direction: an edge u->v where
u is unreachable (disc[u] = -1) and v is reachable also passes the condition
without triggering a recompute (though that case is less likely to violate
the contract since v's times are already set; still, the parent/forest
structure could be affected).

## REPAIR_HINTS
The fix is to add a check in `insert_edge` for the case where the new edge
makes a previously unreachable vertex reachable. Specifically, after updating
`state['adj'][u].add(v)`, also recompute (or do a targeted re-search) when:

1. `disc[v] == -1` (v was unreachable) AND `disc[u] != -1` (u is reachable).
   This is the exact failing case: u=0 is reachable, v=1 was not.

2. More generally, if `disc[u] == -1` (u was unreachable), the new edge
   doesn't change reachability of any previously-reachable vertex, so the
   existing forest on reachable vertices remains valid. No recompute needed
   for the reachable set, but if the verifier checks that all reachable
   vertices are in the tree, this case is fine as-is.

The minimal fix: in `insert_edge`, change the condition to:

```python
if (disc[u] < disc[v] and not _is_ancestor(disc, fin, u, v)) or \
   (disc[v] == -1 and disc[u] != -1):
    return _recompute(graph, state)
```

This catches the forward-cross case (original) and the newly-reachable case.

Note: `_recompute` calls `_dfs_full` which does a full DFS over all vertices
starting from 0, so it correctly handles the newly-reachable vertex. The
`_reattach` function (used on tree-edge deletion) also does a full DFS from
root 0, so it is correct for deletions.

Approaches that will NOT work:
- Simply checking `disc[u] < disc[v]` without handling `disc[v] == -1`
  (the current bug).
- Only checking `not _is_ancestor` without the `disc[u] < disc[v]` guard
  (would miss the case where u is unreachable and v is reachable, though
  that case is benign for the contract).
