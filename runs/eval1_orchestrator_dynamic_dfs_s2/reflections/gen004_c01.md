## FAILURE_DESCRIPTION
Graph: 2 vertices, initial adjacency all zeros (no edges). Operation: `insert_edge(graph, (0, 1), state)`.
- Expected: `parent = {0: None, 1: 0}`, `discover = {0: 0, 1: 1}`, `finish = {1: 2, 0: 3}` (vertex 1 becomes reachable from root 0 via the new edge).
- Actual: `parent = [None, None]`, `discover = [0, -1]`, `finish = [1, -1]` — vertex 1 is still marked unreachable.

## ROOT_CAUSE
`insert_edge` only triggers a recompute when the new edge is a *forward-cross* edge:

```python
def insert_edge(graph, edge, state):
    u, v = edge
    state['adj'][u].add(v)
    disc, fin = state['discover'], state['finish']
    if disc[u] < disc[v] and not _is_ancestor(disc, fin, u, v):
        return _recompute(graph, state)
    return state
```

The condition `disc[u] < disc[v]` is False whenever `disc[v] == -1` (v unreachable), so the recompute is skipped. But an inserted edge `u -> v` with `u` reachable and `v` unreachable makes `v` newly reachable: the DFS forest must gain a new subtree rooted at `v` (with `parent[v] = u` and fresh discover/finish times). The candidate's docstring claim "Otherwise the forest stays valid (no change)" is wrong for exactly this case — the old times leave `v` at -1, which is not a valid DFS of the new graph.

Trace: after `init` on the empty 2-vertex graph, `disc = [0, -1]`, `fin = [1, -1]`, `parent = [None, None]`. Insert `(0,1)`: `disc[0]=0 < disc[1]=-1` is False → no recompute → state returned unchanged. Divergence occurs at this single update; the maintained result first becomes wrong here.

## REPAIR_HINTS
In `insert_edge`, add a second trigger: if `disc[u] != -1` (u reachable) and `disc[v] == -1` (v unreachable), the new edge makes v reachable and the forest must be updated. The minimal correct fix is to recompute in that case too, e.g.:

```python
if disc[u] != -1 and disc[v] == -1:
    return _recompute(graph, state)
if disc[u] < disc[v] and not _is_ancestor(disc, fin, u, v):
    return _recompute(graph, state)
```

(Reusing `_recompute` is fine for correctness; a cheaper local fix would be to attach v as a child of u and assign fresh times, but that must also handle the case where v has outgoing edges to other unreachable vertices — a full recompute avoids that subtlety.)

Also note the symmetric gap: an edge `u -> v` with `disc[u] == -1` and `disc[v] != -1` (u unreachable, v reachable) is a back/cross edge from an unreachable vertex and does NOT affect the root-0 DFS, so no action is needed there — the current code correctly skips it.

Approaches that will NOT work:
- Relying on `_is_ancestor` to catch the unreachable case: `_is_ancestor(disc, fin, u, v)` with `disc[v] = -1` returns `disc[u] <= -1 and ...`, which is False for reachable u, but the outer `disc[u] < disc[v]` guard already excludes it, so the ancestor check is never reached.
- Only fixing `delete_edge`/`_reattach`: the failing case is an insertion, and `_reattach` is not on this path.
