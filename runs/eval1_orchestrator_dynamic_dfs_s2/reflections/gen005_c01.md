## FAILURE_DESCRIPTION
Graph: 2 vertices, empty adjacency matrix (both rows all zeros). Operation: `insert_edge(graph, (0, 1), state)` — the first update in the sequence (sequence_idx 0).

Expected after the insert: vertex 1 becomes reachable from root 0, so the DFS must be `parent = {0: None, 1: 0}`, `discover = {0: 0, 1: 1}`, `finish = {1: 2, 0: 3}`.

Actual returned state: `parent = [None, None]`, `discover = [0, -1]`, `finish = [1, -1]` — vertex 1 is still marked unreachable. The new edge 0->1 was added to `state['adj']` but the DFS forest was never updated, so the state no longer reflects the current graph.

## ROOT_CAUSE
The guard in `insert_edge` only triggers a recompute when the new edge is a *forward-cross* edge:

```python
def insert_edge(graph, edge, state):
    u, v = edge
    state['adj'][u].add(v)
    disc, fin = state['discover'], state['finish']
    if disc[u] < disc[v] and not _is_ancestor(disc, fin, u, v):
        return _recompute(graph, state)
    return state
```

This condition is necessary but not sufficient. It misses the case where the new edge makes a previously **unreachable** vertex reachable. In the failing case, before the insert vertex 1 has `disc[1] = -1` (unreachable). After adding 0->1, the condition evaluates as `disc[0] < disc[1]` → `0 < -1` → `False`, so no recompute happens and vertex 1 stays undiscovered.

The same bug pattern exists for the reverse case: if `disc[u] == -1` (u unreachable) and the new edge u->v points to a reachable v, the condition is also `False` and no recompute happens — but that case is actually harmless (u stays unreachable, forest unchanged), so the only truly broken branch is the "v was unreachable, now reachable" one.

## REPAIR_HINTS
In `insert_edge`, before the forward-cross check, add a reachability check: if the target `v` was unreachable (`disc[v] == -1`) and the source `u` is reachable (`disc[u] != -1`), the new edge makes `v` (and possibly its descendants) reachable, so the forest must be updated. The smallest fix:

```python
def insert_edge(graph, edge, state):
    u, v = edge
    state['adj'][u].add(v)
    disc, fin = state['discover'], state['finish']
    if disc[v] == -1 and disc[u] != -1:
        return _recompute(graph, state)
    if disc[u] < disc[v] and not _is_ancestor(disc, fin, u, v):
        return _recompute(graph, state)
    return state
```

Note: `_recompute` calls `_dfs_full(graph)` which iterates `for s in range(n): if disc[s] == -1: rec(s)` — this starts a new DFS tree from every unreachable vertex, which is fine for the verifier (unreachable vertices are not checked), but it means the "root 0" DFS is not the only tree. This is acceptable per the state contract ("Unreachable vertices are not checked"), but be aware that `_dfs_full`'s multi-source behavior differs from `_reattach`'s single-root behavior. For consistency, consider making `_recompute` also single-root (only start from vertex 0, leave others at -1) so that `discover`/`finish` of unreachable vertices are -1 in both code paths.

Approaches that will NOT work:
- Simply checking `disc[u] < disc[v]` without handling the -1 sentinel: -1 is less than any non-negative discover time, so the comparison silently misbehaves for unreachable vertices.
- Only fixing the `disc[v] == -1` case without also guarding `disc[u] == -1`: if u is unreachable, the edge u->v cannot make v reachable (v is already reachable or not, but u can't be reached from root), so no recompute is needed — but the forward-cross check `disc[u] < disc[v]` with `disc[u] = -1` would be `True` for any reachable v, causing an unnecessary (but not incorrect) recompute. Guarding `disc[u] != -1` in the reachability branch avoids this.
