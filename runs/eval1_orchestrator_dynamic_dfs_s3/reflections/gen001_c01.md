## FAILURE_DESCRIPTION
Case: n=2, initial graph with no edges (state after init: parent=[None,None], discover=[0,-1], finish=[1,-1]). Operation: `insert (0,1)` on the updated graph [[0,1],[0,0]].

- Expected: parent=[None,0], discover=[0,1], finish=[3,2] (vertex 1 reachable, DFS tree edge 0->1).
- Actual: parent=[None,None], discover=[0,-1], finish=[1,-1] — the stale pre-insertion state was returned unchanged.

## ROOT_CAUSE
`insert_edge` (and `delete_edge`) decide whether to recompute by calling `_is_valid_dfs_forest(graph, parent, discover, finish)` on the OLD state against the NEW graph. That check only tests the "no forward-cross edge" half of Lemma 1, and it silently skips every edge whose target is unreachable in the old state:

```python
if discover[v] == -1:
    continue
```

Lemma 1's "no forward-cross edge" condition is necessary but NOT sufficient: it also requires the search tree to be a SPANNING tree of the reachable set. An edge insertion u->v where v was previously unreachable (discover[v] == -1) makes v newly reachable, but the check skips that edge entirely and returns True, so the stale state (with v still marked unreachable) is returned. The forest is no longer spanning, so it is not a valid DFS forest of the new graph.

Trace on the failing case: after insert, graph[0][1]=1. In `_is_valid_dfs_forest`, u=0, v=1: `graph[0][1]` is 1, but `discover[1] == -1` so the edge is skipped; no violation found, returns True; `insert_edge` returns the old state. Vertex 1 is reachable in the new graph but the state says it is not.

## REPAIR_HINTS
Smallest fix: in `insert_edge`, before the validity check, handle the case where the inserted edge's target is not yet reachable. If `discover[edge[1]] == -1` (target unreachable in the old state), the old state is definitely invalid — recompute (or, for a cheaper fix, extend the search from the target: set parent[vt]=u, run DFS from vt with the shared counter continuing from the old counter, and renumber finish times of affected vertices; but recompute is the safe minimal change). Concretely, in `insert_edge`:

```python
u, v = edge
if discover[v] == -1:
    return _make_state(graph)
if _is_valid_dfs_forest(graph, parent, discover, finish):
    return state
return _make_state(graph)
```

Note: `delete_edge` does NOT have this bug — deleting an edge can only remove reachability, and the old forest (a subset of the old reachable set) remains a valid DFS forest of the new graph, so the check is sound there.

Approaches that will NOT work:
- Strengthening `_is_valid_dfs_forest` to also flag edges u->v with discover[v]==-1 as "invalid": this would make the check correct for insertions, but it would also make `delete_edge` always recompute whenever any reachable vertex has an outgoing edge to an unreachable vertex (which is normal and legal), destroying the "avoid recompute" goal. Better to special-case the insertion in `insert_edge` itself.
- Keeping the current check and additionally verifying reachability by running a BFS/DFS from 0: that is a full recompute in disguise; just call `_make_state` directly when `discover[v] == -1`.
