## FAILURE_DESCRIPTION
Case: n=2, initial graph has no edges (only vertex 0 reachable). Operation: `insert (0, 1)`.

- Expected (a valid DFS of the new graph): `parent = {0: None, 1: 0}`, `discover = {0: 0, 1: 1}`, `finish = {1: 2, 0: 3}`.
- Actual returned: `parent = [None, 0]`, `discover = [0, 1]`, `finish = [2, 2]`.

The parent and discover values are correct, but `finish[0] = 2` equals `finish[1] = 2`. The verifier requires the strict nesting `discover[u] < discover[v] < finish[v] < finish[u]` for every tree edge u->v, so `finish[1] < finish[0]` is violated (2 < 2 is false).

## ROOT_CAUSE
In `_search_newly_reachable`, the local re-search assigns times to the newly reachable set S starting at `insert_pos = f[u]` (the old finish time of u, i.e. the position right after u's old subtree). For the failing case: u=0, v=1, S={1}, `insert_pos = f[0] = 1`, so the DFS over S assigns `d[1]=1, f[1]=2` and the counter ends at `t=3`.

The code then does:

```python
# Update u's finish time: u's subtree now includes S, so u finishes later
f[u] += s_size
```

which yields `f[0] = 1 + 1 = 2`. But u's finish time must be the counter value AFTER the whole subtree (old children + S) has been fully explored, i.e. the final counter value `t` (3 here), not `old f[u] + |S|`. The two coincide only when u had no previously explored children (old `f[u] == d[u] + 1`); whenever u already had a child subtree, `old f[u]` is larger than `d[u]+1` and `f[u] += s_size` undercounts u's finish by exactly the size of u's pre-existing subtree. The same undercount propagates to every ancestor of u (their finish times were shifted by `s_size` but should have been shifted by `s_size + (old f[u] - (d[u]+1))`), so the nesting invariant is broken for the whole ancestor chain.

Note the DFS loop over S is itself correct (it produces a proper DFS of S with counter ending at `t`); only the bookkeeping of u's (and ancestors') finish times is wrong.

## REPAIR_HINTS
Smallest fix, inside `_search_newly_reachable`:

1. Keep the shift of all vertices with `discover >= insert_pos` by `s_size` (that part is correct).
2. Do NOT do `f[u] += s_size`. Instead, after the DFS over S finishes, set `f[u] = t` (the final counter value of the S-search). This is correct because u's subtree now spans exactly `[d[u], t)`: its old children (times unchanged, all < insert_pos) plus S (times in `[insert_pos, t)`).
3. For every ancestor a of u (walk `parent` pointers up to the root), set `f[a] = t` as well — their subtrees also now end at the same final counter value. (Equivalently: for each ancestor a, `f[a] = t`.)

Do NOT try to fix this by changing where S is inserted (e.g. inserting S right after `d[u]` instead of after `f[u]`): that would reorder u's children relative to the old DFS order and can create forward-cross edges against u's existing children, breaking Yang's Lemma 1 invariant. The insertion position `f[u]` is correct; only the finish-time bookkeeping needs the fix above.
