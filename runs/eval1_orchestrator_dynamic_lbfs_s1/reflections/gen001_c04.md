## ROOT_CAUSE

The static `_lexbfs` function is **not a correct LexBFS implementation**. It
uses a flawed partition-refinement scheme:

```python
classes = [[v] for v in range(n)]
q = list(range(n))
head = 0
...
v = cls[0]
result.append(v)
# Split cls[1:] by adjacency to v
```

The bug: each class is a **singleton** (`[v]`), so `cls[1:]` is always empty.
The "split" step does nothing — `neigh` and `non` are always empty lists.
The algorithm simply outputs vertices in the order they appear in the queue,
which is just `[0, 1, 2, ..., n-1]` (the initial vertex-id order). It never
actually refines the partition based on adjacency, so it produces the
trivial ordering regardless of the graph structure.

This is not a dynamic-update bug; the static base case is broken. The
partition-refinement LexBFS requires maintaining **multi-element classes**
and splitting them as vertices are output. The correct algorithm starts with
one class containing all vertices, and when a vertex is output from a class,
the remaining vertices in that class are split into neighbors/non-neighbors
of the output vertex, and the queue is updated accordingly.

## REPAIR_HINTS

1. **Fix `_lexbfs` to implement proper partition-refinement LexBFS.**
   The standard algorithm (Habib-McConnell-Paul-Viennot):
   - Start with a single class containing all vertices: `classes = [[0, 1, ..., n-1]]`.
   - Queue contains class indices.
   - When processing a class, output its first vertex `v`, then split the
     remaining vertices in that class into `neigh` (adjacent to v) and
     `non` (not adjacent to v).
   - Replace the current class in the queue with the two new classes
     (neigh first, then non), inserting them at the current position.
   - Continue until all vertices are output.

   The key fix: initialize with `classes = [[v for v in range(n)]]` (one
   class with all vertices) instead of `classes = [[v] for v in range(n)]`
   (n singleton classes). This ensures the split step actually has vertices
   to split.
