## ROOT_CAUSE

The static `_lexbfs` function is **not a correct LexBFS implementation**.
It only refines the class from which the current vertex was drawn, and
ignores all other classes in the queue.

The responsible code:


The bug: when vertex `v` is output from class `ci`, only the remaining
vertices of `classes[ci]` are split into `neigh`/`non`. All other classes
in the queue (at positions `head`, `head+1`, ...) are left completely
untouched. In a correct partition-refinement LexBFS (Habib-McConnell-Paul-
Viennot), **every** class in the queue must be refined by adjacency to `v`:
each class `C` is split into `C ∩ N(v)` (placed before) and `C \ N(v)`
(placed after), preserving the relative order of classes.

## REPAIR_HINTS

Fix `_lexbfs` to implement the correct HMPV partition-refinement LexBFS:

When vertex `v` is output, refine **every** class in the queue (not just the
one `v` came from). The standard algorithm:

```python
def _lexbfs(graph, n):
    adj = _adj_bitsets(graph, n)
    # Single initial class with all vertices in id order
    classes = [list(range(n))]
    q = [0]  # queue of class indices
    head = 0
    result = []

    while head < len(q):
        ci = q[head]
        head += 1
        cls = classes[ci]
        if not cls:
            continue
        v = cls[0]
        result.append(v)
        if len(cls) == 1:
            classes[ci] = []
            continue
        # Remove v from its class; the remainder stays at position ci
        rest = cls[1:]
        classes[ci] = rest  # will be refined below

        # Refine ALL classes in the queue (from head onward, plus ci if rest is non-empty)
        # Standard approach: rebuild the queue from position head
        # For each class, split into (∩ N(v)) and (\ N(v)), neighbor part first
        av = adj[v]
        new_q = []
        # Process classes in order: ci (if rest non-empty) first, then head..end
        # Actually, the standard HMPV: the class that produced v is split
        # in place, and ALL other classes are also split.
        # The queue order is: [split of ci] + [splits of other classes in queue order]

        # Simpler correct approach:
        # 1. Split the current class (ci) into neigh/non by v
        # 2. Split every OTHER class in the queue by v
        # 3. Rebuild queue: [neigh_ci, non_ci] + [for each other class: neigh, non]

        # But the key insight: in HMPV, when you output v from class C,
        # you refine C (split rest into N(v)/~N(v)) AND refine all other
        # classes in the queue. The refined queue is:
        # [C∩N(v), C\N(v)] followed by [D∩N(v), D\N(v) for each other class D]

        # Implementation:
        # First, collect all classes that need refinement (all non-empty classes
        # in the queue from position head, plus ci if it has rest)
        # ci is at position head-1 (just processed), so it's NOT in q[head:]
        # We need to re-insert ci's split at position head

        # Correct implementation:
        all_classes_to_refine = []
        # ci's remainder goes first (it was the front of the queue)
        if rest:
            all_classes_to_refine.append(rest)
        # Then all other classes in queue order (from head to end)
        for qi in range(head, len(q)):
            other_cls = classes[q[qi]]
            if other_cls:
                all_classes_to_refine.append(other_cls)

        # Now split each by adjacency to v
        new_q = []
        for cls_to_split in all_classes_to_refine:
            neigh = [x for x in cls_to_split if (av >> x) & 1]
            non = [x for x in cls_to_split if not (av >> x) & 1]
            if neigh:
                classes.append(neigh)
                new_q.append(len(classes) - 1)
            if non:
                classes.append(non)
                new_q.append(len(classes) - 1)

        # Clear old classes
        classes[ci] = []
        for qi in range(head, len(q)):
            classes[q[qi]] = []

        # Rebuild queue: keep q[:head] (already processed), then new_q
        q = q[:head] + new_q
        # head stays the same (we just replaced q[head:] with new_q)

    return result
```

Key changes from the current code:
1. **Refine ALL classes**, not just the one the vertex came from. The current
   code only splits `cls[1:]` (the remainder of the current class) and
   ignores all other classes in the queue.
2. The split of the current class's remainder goes at the FRONT of the new
   queue segment (position `head`), followed by the splits of other classes
   in their original queue order.

**Approaches that will NOT work:**
- Simply adding a `_check_lb` validation after `_lexbfs` and retrying with
  a different start vertex: the algorithm is structurally broken (it doesn't
  refine all classes), so no start vertex will fix it.
- Using the "move u/v to each position" local repair as a substitute for a
  correct static LexBFS: the local repair is only a heuristic and cannot
  guarantee finding a valid ordering for arbitrary graphs.
- Keeping the current "only refine the current class" logic but adding a
  second pass: the refinement must happen in a single pass per vertex output,
  because the queue order after refinement depends on the adjacency to the
  just-output vertex.
