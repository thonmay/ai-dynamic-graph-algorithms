## FAILURE_DESCRIPTION
3-vertex undirected graph, initial state (sequence_idx 0): edges {0-1, 1-2} (path 0-1-2). `init` produced the valid LexBFS ordering [0, 1, 2]. Then `insert_edge(graph, (0, 2), state)` makes the graph the triangle K3. The candidate returned the old ordering [0, 1, 2] (result "[0, 1, 2]"), but the verifier expected [0, 2, 1] and reported a (LB) violation at a=0, b=1, c=2 (pos_a=0, minD=1e9 = no witness found). In K3, for positions a=0 < b=1 < c=2: ac=0-2 in E, ab=0-1 in E — the brief's stated orientation (ac in E, ab not in E) is not the violated one; the violated orientation is the other one, ab in E with ac in E but the witness condition fails. Concretely the verifier's check for this triple found no d < a with db in E and dc not in E (vacuously impossible since a is at position 0, prefix empty).

## ROOT_CAUSE
`_certify` (lines ~70-95) is a wrong certificate: it checks the (LB) 4-point property in only ONE of the two required orientations. The loop body is:

```python
cands = after[j] & (na ^ nb)
...
if (nb & ~bs[cc] & prefix) == 0:
    return False
```

For every c in N(a) Δ N(b) it demands a witness d < a with **d~b and not d~c**. This is the correct witness only when c ∈ N(b) \ N(a) (i.e. ab in E, ac not in E). When c ∈ N(a) \ N(b) (ab not in E, ac in E — the orientation stated in the brief), the required witness is **d~c and not d~b**, but the code still tests `nb & ~bs[cc] & prefix`, which is the wrong adjacency pair.

Tracing the failing case: order [0,1,2], K3, i=0 (a=0), j=1 (b=1), prefix = P[0] = 0 (empty). cands = after[1] & (N(0) Δ N(1)) = {2} & ({1,2} Δ {0,2}) = {2} & {0,1} = ∅ — so the code never even inspects c=2 and returns True, keeping the invalid ordering. The reference `_certify_ref` has the same single-orientation bug (it skips when `ab == ac` and only ever looks for d~b and not d~c), so it cannot be used as a cross-check either.

Note the deeper issue: the brief's stated property "for all a < b < c with ac in E and ab not in E, ∃ d < a with db in E and dc not in E" is itself not a valid certificate for LexBFS (it is vacuously true for the invalid ordering [0,1,2] in K3, since ab=0-1 is an edge, so the premise never fires). The actual Corneil–Krueger (LB) property requires the witness condition for BOTH orientations of the a/b adjacency mismatch to c, with the witness's adjacency to b and c matching the orientation:
- c ∈ N(b) \ N(a): ∃ d < a with d~b and not d~c
- c ∈ N(a) \ N(b): ∃ d < a with d~c and not d~b

## REPAIR_HINTS
1. In `_certify`, split `cands` into the two orientations and use the matching witness test:
   - `cands_b = after[j] & nb & ~na` → require `(nb & ~bs[cc] & prefix) != 0` (d~b, not d~c)
   - `cands_a = after[j] & na & ~nb` → require `(bs[cc] & ~nb & prefix) != 0` (d~c, not d~b)
   Return False if either required witness set is empty.
2. Fix `_certify_ref` the same way (it currently only checks the d~b / not d~c witness and skips the ab==ac case, which is exactly the case that must be checked).
3. Do NOT rely on the brief's one-sided property statement as the certificate — it is insufficient (the failing case is a counterexample: [0,1,2] in K3 satisfies the brief's one-sided property but is not a LexBFS ordering).
4. Do not try to "patch" by only re-checking triples involving the updated edge: the certificate is global and the current ordering may already be invalid for unrelated triples; the full (corrected) certificate check is the safe fallback.
5. After fixing `_certify`, sanity-check it against `_certify_ref` (also fixed) on random small graphs, and against a brute-force "is this a valid LexBFS ordering" check (e.g. verify the ordering can be produced by some LexBFS tie-breaking, or verify the full two-orientation (LB) property).
