## REPAIR_HINTS
1. **Replace `_lexbfs` with a correct LexBFS implementation.** The standard approach is the partition-refinement (Habib-McConnell-Paul-Viennot) algorithm, or equivalently a BFS-based approach:
   - Use a queue (or list) of "active" vertices.
   - Start with vertex 0 (or any vertex) in the queue.
   - Repeatedly take the first active vertex, output it, then for each remaining vertex, update its label (append 1 if adjacent to the output vertex, 0 otherwise).
   - The key difference from the current code: the selection must be **FIFO among vertices with the same label**, not "smallest label overall." In practice, the standard LexBFS maintains a list of buckets (one per distinct label) and processes them in order; within a bucket, vertices are processed in the order they were added.
   - A simpler correct implementation: use the standard "label + queue" approach where you maintain a list of (label, vertex) pairs sorted by label, and when a vertex is selected, you update labels of all remaining vertices and re-sort (stable sort to preserve insertion order for equal labels).

2. **The `_is_valid_lexbfs` checker appears correct** — it properly implements the 4-point property. The issue is purely in `_lexbfs`.

3. **Do NOT try to fix the greedy selection by changing the tie-break.** The problem is not the tie-break; it's that the greedy "pick smallest label" rule fundamentally violates BFS layering. Even with a different tie-break, the algorithm would still pick non-neighbors before neighbors when their labels happen to be lexicographically smaller.

4. **The local repair and fallback logic in `insert_edge`/`delete_edge` is fine in principle** — once `_lexbfs` is correct, the fallback will produce valid orderings. The `_is_valid_lexbfs` check and `_try_local_repair` can remain as-is.
