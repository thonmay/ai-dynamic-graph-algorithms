## FAILURE_DESCRIPTION
Operation: `init` on a 3-vertex undirected graph (sequence_idx 0, no prior state).
Result returned: `[0, 2, 1]`. Expected: `[0, 1, 2]`.
The verifier reports a (LB) 4-point violation with a=0, b=2, c=1 (vertex ids),
pos_a=0, minD=1000000000 (sentinel: no witness d found).

Reconstructing the graph from the violation: in the returned ordering
`[0, 2, 1]`, the triple (a=0, b=2, c=1) means:
- A[0][2] = 0 (ab not in E)
- A[0][1] = 1 (ac in E)
- no d before position 0 exists (a is first), so the property is violated.

The only graph consistent with this is the path 0-1-2:
A = [[0,1,0],[1,0,1],[0,1,0]].

## ROOT_CAUSE
The bug is in `_lexbfs_full`, specifically the label comparison direction:

```python
best = min(unprocessed, key=lambda v: (labels[v], v))
```

This picks the vertex with the **lexicographically smallest** label. However,
LexBFS requires picking the vertex with the **lexicographically largest** label
(more 1s = more neighbors already processed = "most connected" to the
already-ordered prefix).

Trace on path 0-1-2:
1. All labels empty. `min` picks vertex 0 (smallest id). order=[0].
   Labels: 1→[1], 2→[0].
2. `min` picks vertex 2 (label [0] < [1]). order=[0,2].
   Labels: 1→[1,1].
3. Pick vertex 1. order=[0,2,1].

Result `[0,2,1]` violates (LB): at positions a=0(v=0), b=1(v=2), c=2(v=1),
we have A[0][2]=0 (ab∉E) and A[0][1]=1 (ac∈E), but no d<0 exists.

With the correct "largest label" rule:
1. Pick 0. Labels: 1→[1], 2→[0].
2. `max` picks vertex 1 (label [1] > [0]). order=[0,1].
   Labels: 2→[0,1].
3. Pick 2. order=[0,1,2]. ✓ Valid.

## REPAIR_HINTS
In `_lexbfs_full`, change the selection from `min` to `max` on the label:

```python
# BUGGY:
best = min(unprocessed, key=lambda v: (labels[v], v))

# FIXED (largest label wins; smaller vertex id breaks ties):
best = max(unprocessed, key=lambda v: (labels[v], [-x for x in []]))  # no
# Simpler:
best = min(unprocessed, key=lambda v: ([-x for x in labels[v]], v))
```

Or most cleanly:
```python
best = max(unprocessed, key=lambda v: (labels[v],))
# then break ties by min vertex id if needed:
# best = min([v for v in unprocessed if labels[v] == max_label], key=lambda v: v)
```

The simplest correct one-liner:
```python
best = min(unprocessed, key=lambda v: ([-x for x in labels[v]], v))
```
This negates each label bit so that `min` effectively picks the largest label,
and breaks ties by smallest vertex id.

Note: `_check_lb` and `_local_repair` are correct as written. The only bug is
the comparison direction in `_lexbfs_full`. The tie-break by vertex id is fine
(any deterministic tie-break is valid for LexBFS); the critical fix is the
min→max direction on the label tuple.
