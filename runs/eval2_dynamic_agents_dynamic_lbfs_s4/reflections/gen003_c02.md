## FAILURE_DESCRIPTION

3-vertex graph, initial state (sequence_idx 0) is the empty graph (no edges).
`init` produced ordering `[0, 1, 2]` (valid for the empty graph). The update
is `insert (0, 2)`, giving the single-edge graph with E = {(0,2)}.

- Expected: `[0, 2, 1]` (the only valid LexBFS ordering of this graph).
- Actual: `[0, 1, 2]` — the stale ordering was kept.
- Verifier violation: a=0, b=1, c=2, pos_a=0, minD=1000000000 (sentinel =
  "no witness d found"). Indeed, in `[0,1,2]` on graph E={(0,2)}:
  a=0, b=1, c=2 with a<c (edge 0-2), a not adj b (no edge 0-1), and there is
  no d < a (a is at position 0), so the (LB) 4-point property is violated.

## ROOT_CAUSE

The bug is in `_check_lb_property`: it is a false-positive checker, so
`insert_edge`/`delete_edge` keep an invalid ordering instead of recomputing.

The intended logic (per the comments) is: for a triple (a,b,c) with
pa < pb < pc, a adj c, a not adj b, the property fails iff c is adjacent to
EVERY d in D_b with pos[d] < pa, i.e.

    alladj[pa] = intersection over {d in D_b : pos[d] < pa} of adj[d]

The code instead computes:

    for pa in range(pb):
        if pa == 0:
            cur = set()
        else:
            cur = cur & adj[D_b[pa - 1][1]]
        alladj[pa] = cur

Two defects:

1. **Wrong index — off-by-one.** `D_b` is indexed by its own list position
   (0,1,2,...), but the loop variable `pa` is a *position in the ordering*.
   `D_b[pa-1]` is only the (pa-1)-th vertex of D_b, not "the d in D_b with
   pos[d] == pa-1". The correct set of d's to intersect is
   `{D_b[i] : D_b[i][0] < pa}` (all D_b entries whose ordering position is
   below pa), which is a prefix of D_b of length `bisect_left([p for p,_ in
   D_b], pa)`, not length pa.

2. **`cur = set()` at pa == 0.** The empty set is the identity for
   intersection, so `alladj[0] = set()` and `c in alladj[0]` is always False:
   the checker can never report a violation for a at position 0. But that is
   exactly the case that fails here: a=0 is at position 0, so the loop
   `for pa in range(pb)` with pa=0 checks `c in set()` -> False, and the
   violation is missed. (When pa == 0 the intersection is over the empty set,
   which should be the *universal* set — every c is "adjacent to all zero
   d's" — so the condition should fire, not be skipped.)

Trace on the failing case: ordering `[0,1,2]`, graph E={(0,2)}.
pb=1 (b=1): D_b = [] (nothing before 1 is adjacent to 1) -> `continue`.
pb=2 (b=2): D_b = [(0, 0)] (vertex 0 at pos 0 is adjacent to 2).
alladj[0] = set() (defect 2). pa=0: a=0, a not adj b=2? 0 IS adj 2 -> skip.
pa=1: a=1, 1 not adj 2 -> check c at pc=2: c=2, 1 not adj 2 -> skip.
No violation found -> `_check_lb_property` returns True -> `insert_edge`
returns the stale state. The real violation (a=0 at pos 0, b=1, c=2) was
exactly the pa==0 case that defect 2 makes uncheckable.

## REPAIR_HINTS

Smallest fix, inside `_check_lb_property` only (the recompute fallback in
`insert_edge`/`delete_edge` is fine and will then be reached correctly):

1. Replace the `alladj` construction with a correct running intersection over
   the prefix of D_b whose positions are < pa:

       import bisect
       dpos = [p for p, _ in D_b]
       cur = None
       alladj = [None] * pb
       for pa in range(pb):
           k = bisect.bisect_left(dpos, pa)   # # of d in D_b with pos[d] < pa
           if k == 0:
               alladj[pa] = None              # empty intersection = universal
           elif cur is None:
               cur = set(adj[D_b[0][1]])
               alladj[pa] = cur
           else:
               for i in range(k - (len(dpos) - pa) if False else 0, 0):  # see below
                   pass
               # simpler: recompute incrementally
               # maintain cur as intersection of adj[D_b[i]] for i < k:
               # when k grows by 1, cur &= adj[D_b[k-1][1]]
               alladj[pa] = cur

   Concretely, the clean incremental version:

       k = 0
       cur = None
       alladj = [None] * pb
       for pa in range(pb):
           while k < len(D_b) and D_b[k][0] < pa:
               if cur is None:
                   cur = set(adj[D_b[k][1]])
               else:
                   cur &= adj[D_b[k][1]]
               k += 1
           alladj[pa] = cur   # None means "no d with pos < pa" -> universal

2. In the violation test, treat `alladj[pa] is None` as a violation (the
   universal set contains c):

       if alladj[pa] is None or c in alladj[pa]:
           return False

   This fixes the pa==0 case: with no d before a, the 4-point property
   requires no witness, so any (a,b,c) with a adj c and a not adj b is a
   violation.

Do NOT "fix" this by special-casing pa==0 to `cur = set(range(n))` while
keeping `D_b[pa-1]` — the off-by-one (defect 1) still miscomputes
alladj[pa] for pa >= 1 whenever D_b has gaps (e.g. D_b = [(0,x),(2,y)] and
pa=2 must intersect over {x,y}, but `D_b[1]` alone gives only {y}).

Alternative (simpler, still correct): drop the alladj optimization entirely
and check the property directly in O(n^4) — for each (pa,pb,pc) triple with
a adj c and a not adj b, scan d over positions < pa for one with d adj b and
d not adj c. Given the candidate already falls back to a full recompute on
any detected violation, the checker only needs to be correct, not fast.
