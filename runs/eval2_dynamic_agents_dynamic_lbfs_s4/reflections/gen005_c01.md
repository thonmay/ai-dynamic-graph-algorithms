## FAILURE_DESCRIPTION
n=3. Initial graph has only edge (0,1); `init` returns ordering `[0,1,2]` (valid for that graph).
Operation: `insert (0,2)`. New graph edges: {01, 02}.
- Expected: any valid LexBFS of the new graph, e.g. `[0,2,1]` (start 0: N(0)={1,2}; pick 1 first, then 2's non-neighbor 1 must come after 2).
- Actual returned: `[0,1,2]` (the stale ordering, kept because `_check_lb_property` returned True).
- Verifier violation: a=0, b=1, c=2 at positions 0<1<2 with ac=02 in E, ab=01 not in E (per the verifier's convention), and `minD = 1e9` — i.e. no witness d < a exists, so the (LB) property is violated.

## ROOT_CAUSE
`_check_lb_property` implements the WRONG certificate. It checks the 4-point condition
"for all a<b<c<d: NOT (ac in E AND ab not in E AND bd in E AND cd not in E)"
(a forbidden 4-tuple pattern), but the (LB) characterization of Corneil–Krueger is a
3-point EXISTENTIAL property:

  for all positions a < b < c with ac in E and ab not in E,
  there exists d < a with db in E and dc not in E.

The candidate's 4-point pattern is not equivalent to (LB); it is strictly weaker.
On the failing case, the violating triple is (a,b,c) = (0,1,2) at positions
(0,1,2): ac=02 in E, ab=01 not in E (verifier convention), and the required witness
d < a does not exist (a is at position 0, so no d exists at all). The candidate's
checker can only fire on 4-tuples a<b<c<d; with n=3 there are no 4-tuples, so it
returns True and the stale ordering is kept. Even for n>=4 the 4-point pattern does
not capture (LB) violations where the witness d is missing.

Responsible code: the entire body of `_check_lb_property` (the nested
`for pb ... for pd ... for pa ... for c in C` loops) — it tests the wrong
property, so `insert_edge`/`delete_edge` keep an invalid ordering.

## REPAIR_HINTS
Replace `_check_lb_property` with a direct O(n^4) (or O(n^3) with bitsets) check of
the actual (LB) property, matching the verifier's convention (the verifier reports
a violation for a<b<c with ac in E, ab not in E, and no d < a with db in E and
dc not in E):

```python
def _check_lb_property(graph, ordering):
    n = len(ordering)
    adj = [set() for _ in range(n)]
    for u in range(n):
        for v in range(n):
            if graph[u][v]:
                adj[u].add(v)
    for pa in range(n):
        a = ordering[pa]
        for pb in range(pa + 1, n):
            b = ordering[pb]
            if b in adj[a]:
                continue          # ab in E: condition not met
            for pc in range(pb + 1, n):
                c = ordering[pc]
                if c not in adj[a]:
                    continue      # ac not in E: condition not met
                # need some d < a with db in E and dc not in E
                ok = False
                for pd in range(pa):
                    d = ordering[pd]
                    if d in adj[b] and d not in adj[c]:
                        ok = True
                        break
                if not ok:
                    return False
    return True
```

Notes:
- Keep the rest of the candidate (init + recompute-on-failure) unchanged; once the
  checker is correct, the fallback `_lexbfs` is already a valid static LexBFS, so
  full correctness is restored.
- Do NOT try to "fix" the 4-point pattern by adding more 4-tuple cases; the (LB)
  certificate is inherently 3-point with an existential witness, and any purely
  4-point forbidden-pattern check will keep missing violations (e.g. when a is at
  position 0, or when the witness d simply does not exist).
- The O(n^4) cost is acceptable for correctness-first; a bitset over positions
  (precompute for each vertex the set of earlier positions adjacent to it) can
  reduce the inner witness search to O(n^3) word ops later.
