## ROOT_CAUSE
`_check_lb_property` returned `True` for the invalid ordering `[0,1,2,3]`, so `insert_edge` kept the stale state instead of recomputing. The bug is in the `S == 0` branch:

```python
S = D_b & mask_lt_pa
if S == 0:
    if c_candidates != 0:
        return False
    continue
```

`S` is the set of d with pos[d] < pa and d adj b. When `S == 0`, the code declares a violation for *any* c in `c_candidates` (neighbors of a at positions > pb). But the 4-point property only requires a witness d for a *specific* c: "there exists d < a with db in E and dc not in E". If `S == 0`, then for every c the witness set is empty — so a violation exists iff `c_candidates != 0`... that part is actually correct.

The real bug is in the `S != 0` branch:

```python
if (S & ~adj_bits[c]) != 0:
    return False
```

This is inverted. The property requires: for all c in c_candidates, there EXISTS d in S with d NOT adjacent to c. The code returns False (violation) when such a d exists — i.e. it treats a *satisfied* property as a violation and vice versa. The correct test is: violation iff for some c, `(S & ~adj_bits[c]) == 0` (no d in S is non-adjacent to c).

Tracing the failing case: ordering `[0,1,2,3]`, graph edges {0-1, 0-3, 1-3, 2-3}. pb=2 (b=2): D_b = {3} (3 adj 2, pos 3 > 2 — no, D_b needs pos < pb=2, so d in {0,1}: 0-2 not in E, 1-2 not in E, so D_b = 0). pa=1 (a=1): ab = 1-2 not in E ✓. c_candidates = N(1) ∩ {pos>2} = {3} (1-3 in E). In `_check_lb_property`, fix the inverted condition in the `S != 0` branch:

```python

# CORRECT: violation iff no d in S is non-adjacent to c
if (S & ~adj_bits[c]) == 0:

```

Also mask `~adj_bits[c]` to n bits to avoid Python's infinite-sign-bit issue: use `(~adj_bits[c]) & ((1 << n) - 1)` or equivalently check `(S | adj_bits[c]) != S` is false, i.e. `S & ~adj_bits[c] == 0`.
