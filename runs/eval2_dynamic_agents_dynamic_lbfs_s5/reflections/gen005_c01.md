## FAILURE_DESCRIPTION
After `insert (2, 0)` on a 4-vertex graph, the candidate returned ordering `[0, 2, 1, 3]`. The verifier rejected it: with positions a=1 (vertex 2), b=2 (vertex 1), c=3 (vertex 3), the (LB) 4-point property is violated — `ac in E` (edge 2–3 present), `ab not in E` (edge 2–1 absent), and no `d < a` (only d=0, vertex 0) satisfies `db in E and dc not in E`. The expected valid ordering was `[0, 2, 3, 1]`.

## ROOT_CAUSE
The static `_lexbfs` is not a correct LexBFS. It uses a FIFO queue of buckets and, when processing bucket B, splits the *entire* remainder of B into B1 (neighbors of v) and B2 (non-neighbors of v), appending both to the end of the queue. This is wrong in two ways:

1. **B2 is never refined.** In true LexBFS, the non-neighbor part of a bucket must be refined by *every* vertex that is output later (each later vertex w splits the current bucket into N(w) and non-N(w)). Here B2 is enqueued once and, when it is eventually popped, only its first vertex is used to split it — the other vertices that were output before B2 was processed never refine it. So B2's vertices keep stale labels.

2. **B1 is refined too late.** B1 (neighbors of v) is appended to the end of the queue, so it is only split by the first vertex of B1 itself, not by v's successors that are output before B1 is processed.

Concrete trace on the failing graph (edges: 0–2, 0–3, 2–3; 1 isolated):
- B=[0,1,2,3], output 0; B1=[2,3], B2=[1]; queue: [B1, B2].
- Pop B1=[2,3], output 2; split by 2: B1'=[3], B2'=[]; queue: [B2, B1'].
- Pop B2=[1], output 1. **1 was never refined by vertex 2** (2 was output before 1, and 2 is adjacent to 3 but not to 1 — that distinction is exactly what the (LB) property needs).
- Pop B1'=[3], output 3.
Result `[0,2,1,3]`. Correct LexBFS would refine the bucket containing 1 by vertex 2 before outputting 1, yielding `[0,2,3,1]`.

The bug is in the bucket-processing loop of `_lexbfs` (the `buckets.append(B1)` / `buckets.append(B2)` FIFO scheme). The docstring's claim that "breadth-first refinement ... yields the lexicographic property" is false: LexBFS requires that each bucket be refined by *all* vertices output since the bucket was last split, not just by the first vertex of the bucket.

## REPAIR_HINTS
Replace `_lexbfs` with a correct static LexBFS. The simplest correct approach on the matrix (O(n^2)):

- Maintain a list of buckets (each a list of vertices) in output order.
- Iterate over the buckets in order; for the current bucket B, output its first vertex v, then split the *rest* of B into B1 (adjacent to v) and B2 (not adjacent to v), replacing B in place with [B1, B2] (B1 before B2, both non-empty only if non-empty).
- **Crucially:** after outputting v, also refine *every subsequent bucket* in the list by v (split each into N(v)/non-N(v), in place, preserving order). This is the step the candidate omits.

Equivalently, use the standard label-based formulation: keep a list of buckets; for each vertex v in the order in which it is output, refine all buckets that come after v's bucket by v. A clean O(n^2) implementation:

```python
def _lexbfs(adj, n):
    buckets = [list(range(n))]
    order = []
    i = 0
    while i < len(buckets):
        B = buckets[i]
        if not B:
            i += 1
            continue
        v = B[0]
        order.append(v)
        # split B's remainder by v, in place
        rest = B[1:]
        B1 = [x for x in rest if adj[v][x]]
        B2 = [x for x in rest if not adj[v][x]]
        buckets[i] = B1
        if B2:
            buckets.insert(i + 1, B2)
        # refine all later buckets by v
        for j in range(i + 1, len(buckets)):
            Bj = buckets[j]
            if len(Bj) <= 1:
                continue
            C1 = [x for x in Bj if adj[v][x]]
            C2 = [x for x in Bj if not adj[v][x]]
            if C1 and C2:
                buckets[j] = C1
                buckets.insert(j + 1, C2)
        i += 1
    return order
```

This is still a full recompute per update (same as the candidate), but it is *correct*. Do not try to "fix" the FIFO scheme by reordering the queue — the missing refinement of later buckets is the essential defect, and any scheme that only splits a bucket by its own first vertex will fail the (LB) property on graphs like the failing one.
