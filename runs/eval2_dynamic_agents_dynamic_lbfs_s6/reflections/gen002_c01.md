## ROOT_CAUSE

`init` calls `_lexbfs_canonical`, which is a copy-paste of `_lexbfs_full` with the
"canonical" tie-break never actually implemented. The bug is in the bucket-refinement
step, which violates the partition-refinement invariant that **every non-empty bucket
in P appears in Q exactly once**.

Responsible lines (identical in `_lexbfs_full`, `_lexbfs_canonical`, `_lexbfs_canonical2`):

```python

            Q.append(b)  # re-enqueue surviving bucket

            Nc = [x for x in b2 if not graph[v][x]]

                newP.append(N)
                Q.append(N)
            if Nc:
                newP.append(Nc)
                Q.append(Nc)
        P = newP
```

The surviving bucket `b` is re-enqueued **before** the split buckets `N`, `Nc` of the
other buckets are enqueued. In the correct HMPV algorithm, the surviving bucket is
re-inserted at the **front of P** (so its next vertex is processed next) but the
enqueuing order in Q must be: first the split buckets of the *other* buckets (in P
order), then the surviving bucket `b`. The current code does the opposite: `b` is
enqueued first, so `b`'s next vertex is processed before the vertices of the newly
split buckets. This changes the lexicographic labels and can produce an ordering that
violates the (LB) property.

## REPAIR_HINTS

The bug is in the bucket-refinement step of `_lexbfs_full`, `_lexbfs_canonical`, and
`_lexbfs_canonical2`. The surviving bucket `b` is NOT refined by the vertex `v` just
taken from it. The fix:

1. After `v = b.pop(0)`, split `b` by `v`'s adjacency:
   ```python
   N_b = [x for x in b if graph[v][x]]
   Nc_b = [x for x in b if not graph[v][x]]
   ```
2. Place `N_b` at the front of `newP` and enqueue it first in `Q`.
3. Place `Nc_b` after the split buckets of the other buckets in `newP` and `Q`.
4. The other buckets are refined as before.

This ensures that the remaining vertices in the surviving bucket are ordered by their
adjacency to `v`, which is required for a valid LexBFS ordering.

The local repair and fallback logic in `insert_edge` and `delete_edge` are fine; the
bug is purely in the static LexBFS routine.
