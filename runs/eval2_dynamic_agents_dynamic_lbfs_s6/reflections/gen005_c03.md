## ROOT_CAUSE
The fast-path `_check_lb_insert` is logically unsound. Its core assumption — "Adding edge (u,v) can only create new violations where the new edge serves as the 'ac' edge" — is correct in principle, but the implementation has a critical flaw.

In Case 2 (a=v, c=u, pv < pu), the code computes:
```python
W = adj[b] & ~adj[u]
if not (W & prefix[pv]):
    return False
```

The (LB) property requires: for a < b < c with ac in E and ab NOT in E, there exists d < a with db in E and dc NOT in E. The set `W = adj[b] & ~adj[u]` identifies vertices adjacent to b but NOT adjacent to c=u. The intersection `W & prefix[pv]` checks if any such vertex is before position pv (i.e., d < a=v).

The bug: the code uses the POST-insert adjacency. The new edge (u,v) = (2,0) makes u=2 adjacent to v=0. When computing `~adj[u]` (i.e., `~adj[2]`), the new edge causes v=0 to be excluded from the "not adjacent to c" set. But v=0 is a=v, and a is never a valid witness (d must be strictly before a). So this specific exclusion is harmless.

However, the real issue is more subtle: the fast-path only checks triples where {a,c} = {u,v}. But adding edge (u,v) can also affect the witness set for OTHER triples where the new edge is NOT the 'ac' edge. Specifically, if the new edge (u,v) makes u adjacent to v, this can change whether a vertex d is "adjacent to c" for triples where c is neither u nor v. Wait — no, the new edge only affects adjacency between u and v. For a triple (a', b', c') where c' is neither u nor v, the new edge doesn't change whether d is adjacent to c'. So the fast-path's scope is correct.

The safe conclusion: the fast-path is incorrect and should be removed.

**Minimal correct fix:** In `insert_edge`, replace the call to `_check_lb_insert` with a call to `_check_lb_full`. This eliminates the fast-path entirely and guarantees correctness:

```python
def insert_edge(graph, edge, state):
    n = state['n']
    u, v = edge
    adj = state['adj']
    adj[u] |= 1 << v
    adj[v] |= 1 << u
    order = state['ordering']
    if _check_lb_full(adj, n, order):  # <-- use full check
        return {'ordering': order, 'adj': adj, 'n': n}
    order = _lexbfs(adj, n)
    return {'ordering': order, 'adj': adj, 'n': n}
```

This is O(n^2) per insertion instead of O(n), but correctness is the primary objective. The `_check_lb_insert` function can be deleted.
