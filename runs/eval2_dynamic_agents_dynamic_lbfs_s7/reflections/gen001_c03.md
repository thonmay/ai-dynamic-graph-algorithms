## FAILURE_DESCRIPTION
Case: `init` on the 2-vertex graph with adjacency matrix
```
[[0, 1],
 [1, 0]]
```
i.e. a single edge (0,1). Expected result `[0, 1]` (the verifier's reference
LexBFS, which starts at vertex 0 and visits its neighbor 1 next). Actual
result `[0, 0]` — the returned ordering contains vertex 0 twice and omits
vertex 1 entirely, so it is not even a permutation of the vertex set.

## ROOT_CAUSE
The bug is in `_lexbfs` (lines: `order.append(best)` followed by the
refinement loop). The selected vertex `best` is appended to `order` but is
**never removed from its bucket**. On the next iteration the first non-empty
bucket is still the one containing `best` (its label is the shortest, so it
wins the `min` again), and `best` is appended a second time.

Trace on the failing case:
- Iteration 1: `buckets = [[0],[1]]`, first non-empty bucket is `[0]`,
  `best = 0`, `order = [0]`. Refine by adjacency to 0: bucket `[0]` splits
  into inside `[0]` (self-loop entry `graph[0][0] == 0`? no — `graph[0][0]=0`,
  so 0 goes to *outside*... actually `graph[0][0] = 0`, so `inside=[]`,
  `outside=[0]`), bucket `[1]` splits into inside `[1]` (`graph[1][0]=1`),
  outside `[]`. New buckets: `[[], [0], [1], []]`.
- Iteration 2: first non-empty bucket is `[0]` (index 1). `best = 0` again
  (only member). `order = [0, 0]`. Refine: `graph[0][0]=0` → 0 stays outside.
- Iteration 3: first non-empty bucket is `[0]` again → `order = [0, 0, 0]`...
  but the loop runs exactly `n = 2` times, so it stops after iteration 2.

Result: `[0, 0]`. Vertex 1 is never selected because the algorithm keeps
re-picking 0 from the bucket that should have been emptied.

The responsible lines:
```python
best = min(buckets[bi], key=lambda v: (labels[v], v))
order.append(best)
# refine every bucket by adjacency to best
```
There is no `buckets[bi].remove(best)` (or equivalent) between these.

## REPAIR_HINTS
Smallest fix: after `order.append(best)`, remove `best` from its bucket
before (or during) the refinement step, e.g.:

```python
best = min(buckets[bi], key=lambda v: (labels[v], v))
order.append(best)
buckets[bi].remove(best)          # <-- add this line
```

Then the refinement loop can proceed as-is (the emptied bucket will split
into two empty buckets, which is harmless).

Notes:
- Do NOT change the tie-break or the refinement logic; they are correct.
- The `labels` bookkeeping is fine once the vertex is removed from the
  bucket (it will no longer be a candidate).
- After this fix, the static `_lexbfs` produces a valid permutation and a
  valid LexBFS ordering for any graph; the dynamic wrappers
  (`insert_edge`/`delete_edge`) simply recompute, which is correct (though
  not efficient).
- An alternative that also works: skip `best` during refinement by
  filtering it out of `inside`/`outside` and marking its bucket empty, but
  the explicit `remove` is the clearest minimal change.
