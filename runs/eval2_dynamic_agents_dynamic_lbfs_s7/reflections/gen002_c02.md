## ROOT_CAUSE
The static `_lexbfs` is not a correct LexBFS. The bug is in the refinement loop:

```python
    for x in range(n):
        # find bucket of x
        bx = bidx[x]
        # refine: for each bucket B != bx, split into B∩N(x) and B\N(x)
        # process buckets in order; new buckets keep relative order
        new_buckets = []
        for bi, B in enumerate(buckets):
            if bi == bx:
                new_buckets.append(B)
                continue
            B1 = [v for v in B if v in nbrs[x]]
            B2 = [v for v in B if v not in nbrs[x]]
            if B1:
                new_buckets.append(B1)
            if B2:
                new_buckets.append(B2)
        buckets = new_buckets
```

Two fundamental defects:

1. **The vertex `x` is never removed from its bucket.** The loop iterates `for x in range(n)` and refines by `x`, but `x` stays in `buckets[bx]` (the `if bi == bx: new_buckets.append(B)` branch keeps it). So `x` remains a member of a bucket and can be "selected" again in a later iteration. In the failing trace (graph E = {(0,1), (0,2), (1,3)}, start=0):
   - Initial buckets: `[[0], [1], [2], [3]]`.
   - x=0: refine by 0. Bucket [0] kept as-is (0 still inside). [1]→[1] (1∈N(0)), [2]→[2] (2∈N(0)), [3]→[3] (3∉N(0)). Buckets: `[[0],[1],[2],[3]]`.
   - x=1: refine by 1. [0]→[0] (0∈N(1)), [1] kept (1 still inside), [2]→[2] (2∉N(1)), [3]→[3] (3∈N(1)). Buckets: `[[0],[1],[2],[3]]`.
   - x=2: refine by 2. [0]→[0] (0∈N(2)), [1]→[1] (1∉N(2)), [2] kept, [3]→[3] (3∉N(2)). Buckets: `[[0],[1],[2],[3]]`.
   - x=3: refine by 3. [0]→[0] (0∉N(3)), [1]→[1] (1∈N(3)), [2]→[2] (2∉N(3)), [3] kept. Buckets: `[[0],[1],[2],[3]]`.
   - Ordering: vertices in bucket order, within bucket by id → `[0,1,2,3]`.

   The refinement never actually splits any bucket because every bucket is a singleton — splitting a singleton by adjacency to x just puts it in B1 or B2, both singletons, and the relative order is preserved. The algorithm degenerates to "return vertices in id order" whenever all buckets are singletons, which is the initial state.

2. **The selection order is wrong.** LexBFS selects the next vertex from the front of the bucket queue (the first non-empty bucket), not in id order. The `for x in range(n)` loop processes vertices in id order regardless of bucket position, which is not how LexBFS works.

The correct HMPV LexBFS:
- Initialize: queue = [[start], [v for v in range(n) if v != start]] (or all singletons in id order with start first).
- For each of n steps: take the front non-empty bucket, select a vertex v from it (any tie-break), remove v from the bucket, append v to the ordering, then refine every remaining bucket by adjacency to v (split into N(v) and non-N(v), with N(v) part staying in place and non-N(v) part appended to the end of the queue).

The candidate's `_lexbfs` does none of this correctly. It never removes vertices from buckets, never selects from the front of a queue, and the refinement is keyed on `x` (the loop variable) rather than on the selected vertex.

The `_recompute` function calls `_lexbfs(graph, start=0)` and checks with `_is_valid_lexbfs`. Since `_lexbfs` returns `[0,1,2,3]` (the id order), and `_is_valid_lexbfs([0,1,2,3], graph)` returns False (the violation is real), `_recompute` tries start=1,2,3. But `_lexbfs` with any start still returns the id order (because the refinement is a no-op on singleton buckets), so all starts produce `[0,1,2,3]`, all fail the validity check, and `_recompute` falls through to the final `return _lexbfs(graph, start=0)` which is also `[0,1,2,3]`. The invalid ordering is returned.

## REPAIR_HINTS
Rewrite `_lexbfs` as the standard HMPV partition-refinement LexBFS:

```python
def _lexbfs(graph, start=None):
    n = len(graph)
    if n == 0:
        return []
    if start is None:
        start = 0
    nbrs = [set() for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if graph[i][j]:
                nbrs[i].add(j)
    # Queue of buckets; start first, rest in id order
    buckets = [[start]] + [[v] for v in range(n) if v != start]
    ordering = []
    for _ in range(n):
        # Find front non-empty bucket
        bi = 0
        while bi < len(buckets) and not buckets[bi]:
            bi += 1
        # Select vertex from front bucket (any tie-break; use min id)
        v = min(buckets[bi])
        buckets[bi].remove(v)
        ordering.append(v)
        # Refine every bucket by adjacency to v
        new_buckets = []
        tail = []
        for B in buckets:
            if not B:
                continue
            B1 = [x for x in B if x in nbrs[v]]
            B2 = [x for x in B if x not in nbrs[v]]
            if B1:
                new_buckets.append(B1)
            if B2:
                tail.append(B2)
        buckets = new_buckets + tail
    return ordering
```

Key points:
- Select from the FRONT non-empty bucket, not in id order.
- Remove the selected vertex from its bucket before refining.
- Refine by the SELECTED vertex v, not by a loop variable.
- Neighbor parts stay in place (same queue position), non-neighbor parts appended to the end.
- The `for x in range(n)` loop must be replaced with a `for _ in range(n)` loop that selects from the queue.

Do NOT keep the current `for x in range(n)` structure — it is fundamentally not LexBFS and no amount of tie-breaking or refinement-order adjustment will fix it. The selection order (front of queue) and the removal of the selected vertex are the core of the algorithm.

Once `_lexbfs` is correct, `_recompute` will produce a valid ordering on the first try (start=0), and the `_is_valid_lexbfs` check will pass. The dynamic wrappers (`insert_edge`/`delete_edge`) will then work correctly (recompute-based, which is correct but not efficient).
