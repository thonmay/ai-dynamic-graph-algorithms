## FAILURE_DESCRIPTION
The harness failed before any graph was ever processed: the failing case is
`{"operation": "crash", "error": "Missing function: init"}`. The verifier
requires the three-function interface `init(graph)`, `insert_edge(graph, edge,
state)`, `delete_edge(graph, edge, state)`. The candidate defines only
`insert_edge` and `delete_edge` (plus the private helper `_lexbfs`), so the
very first call, `init(graph)`, raises `NameError: name 'init' is not
defined`. No ordering was ever produced and no LexBFS property was ever
checked — the failure is purely an interface violation, not an algorithmic
one.

## ROOT_CAUSE
The `init` function was never written. The intended body of `init` was
accidentally pasted inside `_lexbfs` after its `return order` statement, so
it is dead code that can never execute:

```python
    return order
    n = len(graph)
    order = _lexbfs(graph)
    return {'ordering': order, 'n': n}
```

(lines immediately after `return order` in `_lexbfs`). Because those lines
are unreachable, the module exposes no `init` symbol at all, and the
verifier's first call crashes with "Missing function: init".

## REPAIR_HINTS
1. Add a top-level `init(graph)` that returns the state dict, e.g.:
   ```python
   def init(graph):
       n = len(graph)
       return {'ordering': _lexbfs(graph), 'n': n}
   ```
   (Computing the initial ordering in `init` is optional but harmless; the
   state only needs to be a dict that `insert_edge`/`delete_edge` can read
   `state['n']` from and return.)
2. Delete the three dead lines after `return order` inside `_lexbfs` — they
   are unreachable and are the source of the misplaced code.
3. Do NOT change the `_lexbfs` algorithm itself: the static routine
   (pick unvisited vertex with lexicographically smallest label of already
   ordered neighbors, ties by vertex id, append picked vertex to each
   unvisited neighbor's label) is a correct LexBFS, and the
   recompute-on-every-update strategy in `insert_edge`/`delete_edge` is
   correct. The only defect is the missing `init` entry point.
4. Note for later generations: once `init` exists, this candidate should
   pass correctness (it recomputes a fresh valid LexBFS after every update);
   the remaining research goal is to avoid the full recompute, which is a
   separate concern from this failure.
