## FAILURE_DESCRIPTION

3-vertex graph, operation `delete (1,2)` at sequence index 0. After deletion the graph has only edge 0-2 (edges 0-1 and 1-2 are absent). The correct LexBFS ordering is `[0, 2, 1]`, but the candidate returned `[0, 1, 2]`.

The (LB) violation in the returned ordering: positions a=0 (v=0), b=1 (v=1), c=2 (v=2). ac=0-2 ∈ E, ab=0-1 ∉ E, and no d < a exists (minD = 10^9 sentinel).

## ROOT_CAUSE

The bug is in `_check_lb`. The (LB) 4-point property is:

> For all positions a < b < c with ac ∈ E and ab ∉ E, there exists d < a with db ∈ E and dc ∉ E.

This is a **conditional** obligation: the witness d is only required when there exists at least one c > b with ac ∈ E. When no such c exists, the condition is vacuously satisfied and no witness is needed.

However, `_check_lb` unconditionally requires a witness. The responsible code:

```python
X = D[a] & N[vb]  # candidates for d
if X == 0:
    return False          # <--- BUG: fires even when cset is empty
# c's: in P[vb], in N[a]
cset = P[vb] & N[a]
while cset:
    ...
```

The `if X == 0: return False` check runs **before** `cset` is computed. When `cset` is empty (no c > b adjacent to a), the property imposes no constraint, but the code still demands a non-empty witness set X.

## REPAIR_HINTS

**The fix:** In `_check_lb`, move the `if X == 0: return False` check to only fire when `cset` is non-empty. The (LB) property only demands a witness when there exists a c > b with ac ∈ E.

Change this:
```python
X = D[a] & N[vb]  # candidates for d
if X == 0:
    return False
cset = P[vb] & N[a]
while cset:
    ...
```

To this:
```python
cset = P[vb] & N[a]
if cset:  # only need witness if there's a c that triggers the condition
    X = D[a] & N[vb]
    if X == 0:
        return False
    while cset:
        ...
```

Or equivalently, compute `cset` first, and only check `X == 0` when `cset != 0`.

**What will NOT work:**
- Adding more repair moves to `_try_repair` — the repair is fine; the problem is the validator.
- Changing `_lexbfs` — it produces correct orderings; the problem is that `_check_lb` rejects them.
- Removing the `_check_lb` call from `_find_valid_order` — this would mask the bug but leave `_try_repair` still using the broken checker, so it would still reject valid repairs and fall through unnecessarily.
