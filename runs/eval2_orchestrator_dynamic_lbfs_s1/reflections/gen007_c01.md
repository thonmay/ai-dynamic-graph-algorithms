## FAILURE_DESCRIPTION
Operation: `init` (sequence_idx 0) on a 4-vertex undirected graph. The candidate returned ordering `[0, 1, 2, 3]`; the expected valid ordering is `[0, 1, 3, 2]`. The verifier reports the (LB) 4-point violation: a=0 (pos 0), b=2 (pos 2), c=3 (pos 3), with 0-2 ∉ E, 0-3 ∈ E, and no d before position 0 to witness the property.

Reconstructing the graph: the 4-cycle with edges {0-1, 1-2, 2-3, 3-0}. In `[0,1,2,3]`, vertex 2 (BFS level 2 from 0) appears before vertex 3 (BFS level 1), which is not even a valid BFS ordering. The valid LexBFS orderings are `[0,1,3,2]` or `[0,3,1,2]`.

## ROOT_CAUSE
The static `_lexbfs` partition-refinement routine uses an **eager** queue discipline that is incorrect. It splits ALL buckets in the queue by N(u) every round and reassembles them as:

```python
if B_n: Q.append(B_n)
for part in n_parts: Q.append(part)
if B_nonn: Q.append(B_nonn)
for part in nonn_parts: Q.append(part)
```

Tracing on the 4-cycle (edges 0-1, 1-2, 2-3, 3-0):

1. Q=[[0,1,2,3]]. Pop B=[0,1,2,3], u=0, B=[1,2,3]. B_n=[1,3], B_nonn=[2]. No other buckets. Q=[[1,3],[2]].
2. Pop B=[1,3], u=1, B=[3]. B_n=[] (3∉N(1)), B_nonn=[3]. Other bucket [2]: 2∈N(1), so n_part=[2], nonn_part=[].
   - Reassembled Q: B_n(empty) + n_parts([[2]]) + B_nonn([3]) + nonn_parts([]) = **[[2],[3]]**.
3. Pop [2], u=2. Pop [3], u=3.
4. Result: **[0,1,2,3]** — invalid (2 is level 2, 3 is level 1).

The correct HMPV algorithm uses a **lazy** discipline: only the front bucket is split each round. B∩N(u) is prepended to the queue; B\N(u) stays at the front. Other buckets are NOT split until they reach the front. With the lazy variant:

1. Q=[[0,1,2,3]]. Pop, u=0, B=[1,2,3]. B_n=[1,3], B_nonn=[2]. Q=[[1,3],[2]].
2. Pop B=[1,3], u=1, B=[3]. B_n=[] (3∉N(1)), B_nonn=[3]. Q=[[3],[2]].
3. Pop [3], u=3. Pop [2], u=2.
4. Result: **[0,1,3,2]** — valid. ✓

The eager splitting of other buckets in step 2 promotes vertex 2 (a neighbor of 1) ahead of vertex 3 (a non-neighbor of 1), violating the BFS-level invariant that LexBFS must respect.

## REPAIR_HINTS
Replace the eager all-bucket splitting in `_lexbfs` with the lazy HMPV discipline. The loop body should be:

```python
while Q:
    B = Q.popleft()
    if not B:
        continue
    u = B[0]
    ordering.append(u)
    B = B[1:]

    # Split ONLY the current bucket B by N(u)
    B_n = [v for v in B if graph[u][v]]
    B_nonn = [v for v in B if not graph[u][v]]

    # Rebuild queue: B_n at front, then B_nonn, then rest of Q unchanged
    new_q = []
    if B_n:
        new_q.append(B_n)
    if B_nonn:
        new_q.append(B_nonn)
    new_q.extend(Q)  # other buckets untouched
    Q = deque(new_q)
```

Do NOT split other buckets. This is the standard lazy HMPV (Habib-McConnell-Paul-Viennot) algorithm and correctly maintains the BFS-level invariant.

**Approaches that will NOT work:**
- Reordering the reassembly (e.g., moving B_nonn after nonn_parts) does not fix the issue; the fundamental problem is that splitting other buckets eagerly changes their internal order relative to B_nonn.
- The `_try_local_repair` and `_is_valid_lexbfs` functions are correct and unaffected; the bug is solely in `_lexbfs`.
- Since the failure is at `init` (no prior state), the local-repair path is never exercised; the fix must be in the static routine.
