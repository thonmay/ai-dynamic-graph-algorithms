bucket — instead of the **first vertex in the bucket's internal order**.

first non-empty bucket. The front is determined by the *history* of

selected vertex, the non-neighbor part stays in front. Using `min(set)` throws
away that history and picks by vertex id, which is not a legal LexBFS
tie-break.

## REPAIR_HINTS
The bug is in `_lexbfs`, in the refinement step. The code appends `rest`
(non-neighbors) before `nb` (neighbors):
```python
if rest:
    new_buckets.append(rest)
new_buckets.append(nb)
```
and then selects from the FIRST non-empty bucket (`bi = 0`). This selects
non-neighbors before neighbors, which is the reverse of LexBFS.

Fix: swap the order so neighbors come first:
```python
if nb:
    rest = b - nb
    if rest:
        new_buckets.append(rest)
    new_buckets.append(nb)
```
becomes:
```python
if nb:
    rest = b - nb
    new_buckets.append(nb)   # neighbors first (larger label)
    if rest:
        new_buckets.append(rest)
```
OR equivalently, keep the current append order but select from the LAST
non-empty bucket instead of the first.

The smallest fix: in the refinement loop, append `nb` before `rest` (or
append `rest` before `nb` and change the selection to scan from the end).
Either way, the next selected vertex must be from the neighbor side of the
split, not the non-neighbor side.

Note: the `min(buckets[bi])` tie-break within a bucket is fine (any
deterministic tie-break is valid for LexBFS), but the bucket ORDER is what
encodes the LexBFS label ordering and must have neighbors before
non-neighbors (when selecting from the front).
