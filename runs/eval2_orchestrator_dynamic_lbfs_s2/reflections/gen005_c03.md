## FAILURE_DESCRIPTION

3-vertex graph, operation `insert (0, 1)` at sequence index 0.
- Initial graph: only edge (1,2) (path 0–1–2 with the 0–1 edge missing).
- After the update: edges (0,1) and (1,2) — a path 0–1–2.
- Expected result: `[0, 1, 2]` (the only valid LexBFS ordering of the path).
- Actual result: `[0, 2, 1]` (the old ordering, kept by the fast path).
- Verifier violation: a=0, b=2, c=1 (positions pos_a=0, pos_b=2, pos_c=1),
  minD = 1e9 (no witness d found).

## ROOT_CAUSE

The fast-path checker `_is_lexbfs` is unsound: it only tests the (LB)
condition for pairs `(b, c)` with **b < c**, but the (LB) property must hold
for **all** position triples a < b < c with ac in E and ab not in E,
regardless of the relative order of b and c. The code:

```python
for c in range(n):
    Nc = adj_pos[c]
    ...
    for b in range(c):
        if not (Nc >> b) & 1:
            continue  # bc not in E
```

only iterates b < c, and `adj_pos[i]` only stores neighbours at positions
**below** i, so the case b > c is never examined.

Trace on the failing case, order = [0, 2, 1], graph edges {01, 12}:
- adj_pos: pos0 (v0) = 0; pos1 (v2) = 01 (adjacent to v0); pos2 (v1) = 11
  (adjacent to v0 and v2).
- The only pair with b < c and bc in E is (b=0, c=1): Bad = (~00) & 01 & 0 = 0
  → passes. The pair (b=1, c=2) is skipped because bc (v2–v1) is not an edge.
- The violating triple has b=2, c=1 (b > c): a=0, ac = v0–v1 in E, ab =
  v0–v2 not in E, and no d < 0 exists. This is never checked, so
  `_is_lexbfs` returns True and the invalid ordering is kept.

Note the candidate's own docstring claims the check is "exactly" the (LB)
property; it is not — it silently assumes b < c.

## REPAIR_HINTS

Smallest fix: in `_is_lexbfs`, iterate over **all** ordered pairs (b, c) with
b != c and bc in E, not just b < c. Concretely, either:

1. Build the full adjacency bitmask for every position (e.g.
   `full_adj[i]` over all j != i), and loop `for c in range(n): for b in
   range(n): if b == c or not (full_adj[c] >> b) & 1: continue`, keeping the
   existing Bad/W/minW logic (it only uses positions < b, so it stays
   correct for b > c as well); or
2. Keep the b < c loop but add a symmetric second pass with the roles of b
   and c swapped (i.e. for c < b with bc in E, compute
   Bad = {a < b : ab not in E and ac in E} using the full adjacency of c,
   and W = {d < b : db in E and dc not in E}).

Do NOT try to "fix" this by restricting the fast path to insertions only or
by adding a heuristic — the checker must be the complete (LB) property for
the fast path to be sound. Also do not change `_lexbfs` (the fallback
recompute is fine; the bug is purely in the fast-path certificate).
