## FAILURE_DESCRIPTION
Operation: `insert (3, 2)` on a 4-vertex graph (sequence_idx 0, i.e. the first update after init).
Result returned: `[0, 1, 2, 3]`. Expected (a valid LexBFS of the updated graph): `[0, 1, 3, 2]`.
Verifier's violation: a=1, b=2, c=3 (positions pos_a=1, i.e. vertices va=1, vb=2, vc=3), with `minD = 1000000000` — the sentinel meaning **no** d < a exists with db in E and dc not in E.

Reconstructed updated graph (the only 4-vertex graph consistent with the violation and the expected order):
- E = {01, 02, 03, 13} (edge 3-2 was just inserted; 1-2 is absent).
- Check: va=1, vb=2, vc=3: 1-2 not in E, 1-3 in E, and d=0 has 0-2 in E but 0-3 not in E → violation.
- Expected order [0,1,3,2] is valid: the only triggered triple is (a=0,b=1,c=2): 0-1 in E so no trigger; (a=0,b=2,c=3): 0-2 in E so no trigger; (a=1,b=2,c=3): 1-2 not in E, 1-3 in E, d=0: 0-2 in E, 0-3 not in E → satisfied.

## ROOT_CAUSE
The static LexBFS `_lexbfs` uses the **wrong refinement direction**. In the partition-refinement formulation, when a vertex v is selected, each other bucket is split so that the **neighbors of v come BEFORE the non-neighbors** (the neighbor part receives the smaller label and is ordered first). The code does the opposite:

```python
# split into non-neighbors (first) and neighbors (second)
non = []
neigh = []
for x in b:
    if adj[v][x]:
        neigh.append(x)
    else:
        non.append(x)
if non:
    # replace bucket j with [non, neigh]
    if neigh:
        buckets[j] = non
        buckets.insert(j + 1, neigh)
```

Tracing on the failing graph (E = {01,02,03,13}):
1. v=0: bucket [1,2,3] → non-neighbors of 0 = [] (0 is adjacent to 1,2,3), so no split. Order [0].
2. v=1: bucket [2,3] → non-neighbors of 1 = [2] (1-2 absent), neighbors = [3]. Code puts [2] before [3]. Order [0,1,2].
3. v=2: bucket [3] → 3 is a non-neighbor of 2, no split. Order [0,1,2,3].

Correct LexBFS would put neighbor 3 before non-neighbor 2 at step 2, giving [0,1,3,2].

**Why the built-in safety net failed:** `_lexbfs_verified` is supposed to catch this via `_verify_lexbfs`, but `_verify_lexbfs` implements the **dual** of the (LB) property (it checks `db in E and dc not in E` for d < a, whereas the (LB) 4-point property requires `db not in E and dc in E`). On the invalid order [0,1,2,3] the dual check happens to pass (d=0 satisfies 0-2 in E, 0-3 not in E), so the verifier returns True and the invalid order is returned. The fallback "try all start vertices" loop is therefore never reached, and even if it were, it uses the same wrong-direction refinement and the same broken verifier.

## REPAIR_HINTS
Two independent bugs must both be fixed (either one alone still fails):

1. **Fix the refinement direction in `_lexbfs`** (and the duplicated loop in `_lexbfs_verified`): swap the two parts so neighbors come first:
   ```python
   if neigh:
       if non:
           buckets[j] = neigh
           buckets.insert(j + 1, non)
           j += 2
       else:
           j += 1   # all neighbors, no split
   else:
       j += 1       # all non-neighbors, no split
   ```
   (i.e. `buckets[j] = neigh`, insert `non` after it when both are non-empty).

2. **Fix `_verify_lexbfs` to the actual (LB) 4-point property**: for all positions a < b < c with ac in E and ab not in E, there must exist d < a with **db NOT in E and dc IN E** (the code currently has `adj[vb][vd] and not adj[vc][vd]`; it must be `not adj[vb][vd] and adj[vc][vd]`).

Approaches that will NOT work:
- Keeping the non-neighbor-first refinement and relying on the "try all start vertices" fallback: every start vertex runs the same wrong-direction refinement, and the broken verifier accepts the invalid order anyway.
- Relying on the verifier alone without fixing the refinement: the verifier is a safety net, not a generator; with the dual property it accepts invalid orders (as this case shows), so it cannot rescue the wrong refinement.
- Note: after both fixes, the recompute-per-update baseline is correct (LexBFS is valid for any tie-break/start); the dynamic-maintenance optimization remains the open research part.
