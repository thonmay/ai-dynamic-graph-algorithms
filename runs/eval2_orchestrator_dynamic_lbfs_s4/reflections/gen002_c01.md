## FAILURE_DESCRIPTION
Failing case: graph_n=2, sequence_idx=0, operation="crash". The very first call, `init(graph)` on a 2-vertex graph, crashes with:

    NameError: name '_all_perms' is not defined at line 91: for perm in _all_perms(order):

No ordering is ever returned, so the verifier sees a crash instead of a result. The crash is deterministic and happens on every `init` call (and on every `_lexbfs` fallback from `insert_edge`/`delete_edge`), because the offending code sits unconditionally inside `_lexbfs`.

## ROOT_CAUSE
`_lexbfs` contains a leftover debug block that was never removed. After the (partial, single-vertex) sanity check it executes:

    for perm in _all_perms(order):
        print('DEBUG perm=%s valid=%s' % (perm, _is_lexbfs(perm, adj)), file=sys.stderr)

`_all_perms` is never defined anywhere in the module (no import, no helper), so the loop raises `NameError` before `_lexbfs` can finish. The surrounding debug prints (`DEBUG n=...`, `DEBUG order=...`, `DEBUG is_lexbfs=...`, `DEBUG done`) are dead weight too.

Note the crash is NOT a logic bug in the LexBFS core: the partition-refinement loop below the debug block (label bitmasks keyed by ordering position, min-label selection with vertex-id tie-break, refinement of unvisited neighbors) is the real algorithm and is never reached. The only divergence point is line 91, the undefined name.

## REPAIR_HINTS
Smallest fix: delete the entire debug block inside `_lexbfs` — from `# debug: dump the graph and ordering to stderr` / `import sys` through `sys.stderr.flush()` (the `print('DEBUG ...')` lines and the `for perm in _all_perms(order):` loop). Keep the `if not _is_lexbfs(order, adj): raise RuntimeError(...)` sanity check if desired, but note it currently only checks the 1-vertex prefix (trivially valid) and is redundant; it can stay or go.

Do NOT try to "fix" the crash by defining `_all_perms` (e.g., `itertools.permutations`) — that would make `init` O(n!) and is the wrong direction; the debug block must simply be removed.

After removal, verify the fallback path end-to-end: `init` on the 2-vertex case, then an `insert_edge`/`delete_edge` that forces the `_lexbfs` fallback (i.e., where `_try_repair` returns None), since that path also runs `_lexbfs` and would have crashed identically.
