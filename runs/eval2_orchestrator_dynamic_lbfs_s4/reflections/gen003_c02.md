## REPAIR_HINTS
In `_is_valid_lexbfs`, the `S == 0` branch has an inverted bitmask test. The line:

```python
if adj_va & middle_mask[a + 1][c]:
    return False
```

should be:

```python
if (~adj_va) & middle_mask[a + 1][c]:
    return False
```

The semantic is: when S is empty (no possible witness d < a), the 4-point property requires that va be adjacent to EVERY vertex at positions a+1..c-1 (otherwise, for any such non-adjacent b, the antecedent "ac in E and ab not in E" holds but no witness d exists). The current code returns False when va IS adjacent to a middle vertex (the opposite of the intended check).

Additionally, the `~adj_va` in the `bad` computation on the line `bad = (~adj_va) & middle_mask[a + 1][c]` has a latent bug: Python integers have infinite sign extension, so `~adj_va` has infinitely many 1-bits above the n-bit range. This is masked by the `& middle_mask[a+1][c]` (which only has bits in the n-bit range), so it works correctly in practice, but it's fragile. A cleaner formulation would be `((1 << n) - 1) ^ adj_va` or equivalently `full_mask ^ adj_va` where `full_mask = (1 << n) - 1`.

The fix is a one-character change (adding `~` before `adj_va` in the S==0 branch, or equivalently changing `adj_va` to `(~adj_va)`). After this fix, the verifier will correctly reject [0,1,2] on the post-insert graph, triggering a recompute that produces a valid ordering.
