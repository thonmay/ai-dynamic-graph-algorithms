The source `_validate` returns bare booleans (`return False` / `return True`) and has no `minD`/sentinel logic. So the executed `_validate` was a different, sentinel-tracking version than the one in the file.

The (LB) witness condition is: for a violation triple (a<b<c, ac∈E, ab∉E) we need some d<a with **d~b AND d⋯c** (adjacent to b, NON-adjacent to c). The most likely bug in the executed validator is that the witness test was written with the `dc` clause negated (treating a vertex adjacent to b but NOT to c as a witness, or equivalently requiring d~c instead of d⋯c), which makes `_validate` return True for orderings that are not LexBFS. That lets `_try_repair` return the invalid swap `[0,2,1]` instead of falling through to the (correct) `_lexbfs` recompute.

## REPAIR_HINTS
1. Make `_validate` a faithful, self-contained (LB) checker and treat it as the single source of truth. Correct reference implementation (no sentinels, no minD):
   ```
   def _validate(order, adj):
       n = len(order)
       for bi in range(n):
           b = order[bi]
           for ci in range(bi+1, n):
               c = order[ci]
               for ai in range(bi):
                   a = order[ai]
                   if adj[a][c] and not adj[a][b]:
                       # need witness d < ai with d~b and d NOT~ c
                       ok = any(adj[d][b] and not adj[d][c] for d in range(ai))
                       if not ok:
                           return False
       return True
   ```
   The witness MUST be `adj[d][b] and not adj[d][c]`. Do NOT use `adj[d][b] and adj[d][c]` (that is the negated-dc bug) and do NOT use a `seen_good` flag that is set by a vertex merely being adjacent to b.
2. Do NOT rely on `_try_repair`'s local moves (swap / move-next-to) to be safe on their own — they are only safe if `_validate` is correct. Keep the `_lexbfs` fallback; it is correct and guarantees termination.
3. After fixing `_validate`, add a self-check in `insert_edge`/`delete_edge`: before returning, assert `_validate(order, adj)`; if it fails, recompute with `_lexbfs`. This makes any residual validator bug fail loudly instead of emitting an invalid ordering.
4. Will NOT work: "fixing" the problem by removing the swap/move candidates from `_try_repair` (the validator is the real defect), or by trusting the ordering from `init`/previous state without re-validating against the NEW adjacency matrix.
5. Note the file/execution mismatch: the recorded `minD` sentinel proves the executed code differed from this source. Ensure the repaired `_validate` (above) is the exact code that runs, and that no stale sentinel-based validator remains.
