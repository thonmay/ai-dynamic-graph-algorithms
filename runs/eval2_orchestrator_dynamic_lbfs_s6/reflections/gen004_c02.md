## FAILURE_DESCRIPTION
Operation: `init` on the 2-vertex graph with adjacency matrix [[2, 2], [2, 2]] (graph_n = 2).
Expected result: `[0, 1]` (a valid LexBFS ordering of the 2 vertices).
Actual result: `[0, 1, 1]` — the ordering contains vertex 1 twice (length 3 instead of 2), so it is not even a permutation of the vertex set.

## ROOT_CAUSE
The bug is in `_static_lexbfs`, in the "split the remainder of the current bucket" block. The remainder is split into `in_N` and `not_N`, and the code appends whichever part(s) are non-empty to `buckets` and enqueues them:

```python
if in_N and not_N:
    buckets.append(in_N)
    buckets.append(not_N)
    q.append(len(buckets) - 2)
    q.append(len(buckets) - 1)
    rem_idx = len(buckets) - 1
elif in_N:
    buckets.append(in_N)
    rem_idx = len(buckets) - 1
elif not_N:
    buckets.append(not_N)
    rem_idx = len(buckets) - 1
```

The `elif in_N` and `elif not_N` branches append the surviving remainder part to `buckets` and set `rem_idx` to it, but they **never enqueue it**. The only place a remainder gets enqueued is the post-loop line `if rem_idx is not None and buckets[rem_idx]: q.append(rem_idx)`, which only runs when the remainder was *never split* (i.e. `rem_idx` was still `None` at the end of the loop).

Trace on the failing case (n=2, adj=[[2,2],[2,2]]):
1. `buckets=[ [0,1] ]`, `q=[0]`. Pop bucket 0, `B=[0,1]`, `buckets[0]=[]`.
2. `idx=0, v=0`: order=[0]. No other buckets. Remainder `rem=B[1:]=[1]`; `in_N=[1]` (adj[0][1]=2≠0), `not_N=[]`. Hits `elif in_N`: `buckets.append([1])` → `buckets=[[], [1]]`, `rem_idx=1`. **Not enqueued.**
3. `idx=1, v=1`: order=[0,1]. No other buckets. `idx+1 == len(B)`, no remainder split.
4. Post-loop: `rem_idx=1` but `buckets[1]` is still `[1]` (non-empty) → `q.append(1)`.
5. Pop bucket 1, `B=[1]`, `buckets[1]=[]`. `idx=0, v=1`: **order.append(1) again** → order=[0,1,1].

So vertex 1 is output twice: once as part of the original bucket's iteration, and again when the un-enqueued remainder bucket is finally enqueued by the post-loop fallback and processed. The invariant "a vertex is output exactly once" is broken.

## REPAIR_HINTS
Smallest fix: in the `elif in_N` and `elif not_N` branches of the remainder-split block in `_static_lexbfs`, enqueue the newly appended bucket (mirroring what the `if in_N and not_N` branch does with `q.append(...)`). E.g.:

```python
elif in_N:
    buckets.append(in_N)
    q.append(len(buckets) - 1)
    rem_idx = len(buckets) - 1
elif not_N:
    buckets.append(not_N)
    q.append(len(buckets) - 1)
    rem_idx = len(buckets) - 1
```

This makes the remainder bucket processed exactly once (as a queued bucket), and the post-loop `if rem_idx is not None and buckets[rem_idx]: q.append(rem_idx)` then finds it already consumed (empty) and does not double-enqueue.

Alternative (equally minimal): guard the post-loop enqueue so it only fires when the remainder was never split, e.g. track a `rem_split` flag set in the three split branches and only do `q.append(rem_idx)` when `rem_split` is False.

Approaches that will NOT work:
- Relying on the post-loop `q.append(rem_idx)` as the sole enqueue for the remainder: it fires too late (after the vertex has already been output during the current bucket's iteration), so the vertex is always double-output whenever the remainder survives a split.
- Removing the post-loop enqueue entirely: then a remainder that was never split (e.g. all remaining vertices adjacent to every earlier vertex, so `in_N` is always the whole remainder) would never be processed and the ordering would be missing vertices.
- The local-repair path (`_try_local_repair`) is not implicated in this failure (it is only used by insert/delete, and the failing op is `init`); do not spend effort there for this case.
