## REPAIR_HINTS
1. **In the `else` branch** (full detach/reattach): replace the "first in-neighbor with dist != -1" logic with "in-neighbor with minimum dist[w]". This ensures the reattached vertex gets the correct BFS distance.

2. **In the `best != -1` branch** (partial reattach): after propagating `dist[x]+1` to tree descendants, add a relaxation pass: for each affected vertex y, check ALL in-neighbors w and set `dist[y] = min(dist[y], dist[w]+1)` if a shorter path exists. This handles the case where a descendant has a non-tree edge giving a shorter distance.

3. **Safest fix**: after any deletion repair, run a full BFS from root over the current graph. This is O(n^2) per deletion but guarantees correctness. Given the goal is "reach full correctness first, then lower the work ratio," this is the recommended immediate fix.

4. **Do NOT** rely on tree-structure propagation alone for deletions — the BFS tree can change topology (a vertex's parent can switch to a non-tree in-neighbor), so the old tree structure is not a valid basis for distance updates.
