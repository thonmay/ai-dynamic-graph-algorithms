\chapter{Conclusion}
\label{ch:conclusion}

\section{Results against commitments and success criteria}

The thesis set out to deliver a research tool with a user interface, an
isomorphism-aware verifier, and cooperative agents, evaluated on a tiered set of
dynamic graph problems. Each registered commitment is assessed below against the
evidence in Chapter~\ref{ch:testing}.

\textbf{C1, the research tool user interface, is fulfilled.} The completion
signal was that the UI can launch, monitor, and replay a multi-generation run
end to end. This was demonstrated with a recorded headless-Chrome run against
the real UI server: a dynamic BFS run was launched from the New Run page,
monitored live as events streamed in, steered with a hint that the engine
acknowledged at generation 2, and replayed with the generation scrubber after it
ended (Section~\ref{sec:test-ui}). The reducer and form logic are unit-tested
(14 Vitest tests, all passing), and access went through a token link and an
HttpOnly cookie.

\textbf{C2, the isomorphism-aware verification engine, is fulfilled.} The
completion signal was that the engine validates known-good algorithms and
rejects known-bad mutations with zero false negatives on $n \le 5$, measured
on the seeded fault corpus. The
self-test drives the real verifier over every isomorphism-class representative
up to $n = 5$ and asserts each verdict. For dynamic DFS, 22 faults are rejected
(15 seeded and 7 one-line mutations of the Yang et al. reference), and the
validate-or-rebuild reference and the Yang et al. fully dynamic DFS are both
accepted. The same self-test repeated with two relabelled copies of every class
(140{,}252 base graphs) gives identical verdicts. For dynamic BFS, 14 seeded
faults are all rejected, and for dynamic LBFS, 12 are all rejected
(Section~\ref{sec:test-selftest}, Table~\ref{tab:selftest}).

\textbf{C3, cooperative agents with optional dynamic agent generation, is
fulfilled for the core signal and reported as a negative result for the
generation variant.} The completion signal was that the system produces a
correct dynamic BFS algorithm within a bounded number of generations without
human intervention. In the orchestrator arm, all nine cells (three problems by
three seeds) reach final-grade PASS, and every cell reaches a search-grade PASS
by generation 3, most in generation 1; for dynamic BFS specifically this is 3 of
3 seeds. The dynamic agent generation mechanism works as designed: 7 of 8 runs
detect an efficiency plateau, spawn a specialist whose focus is written from it,
and retire it. But the outcome is negative: dynamic agents gave the lower final
value in 6 of 8 paired seeds, yet the medians are nearly equal (0.44 versus
0.45), and an exact two-sided Wilcoxon signed-rank test \citep{wilcoxon1945}
gives $p = 0.46$ (Section~\ref{sec:test-evaluation}). The mechanism is sound; at this scale it
does not significantly improve the result.

\section{Deviations and refinements}

The four refinements of Section~\ref{sec:refinements} (certificates instead of
raw equality, undirected LBFS, two-tier bounded grading, and the harness as an
extra baseline) narrow or extend the registered wording; none removes a
registered contribution.

\section{Limitations}

The verification is bounded, not a proof: a fault that only manifests on a
graph larger than five vertices is not caught, which is why the large-graph
benchmark and a 1.44 M random-update check beyond the bound are reported as
supporting evidence. The zero-false-negative result holds only for the seeded
fault corpus, within the graph bound and for the tested operation histories. Two models from a single provider were used, with no
closed frontier model and no Claude Code or Codex sessions. LLM sampling is not
seeded, so only the verifier and the parent selection are reproducible. Small-graph
efficiency does not predict large-graph efficiency for LBFS: the orchestrator's
LBFS candidates are about 2x cheaper than recomputing at $n \le 5$ but about 5x
slower at $n = 128$. Finally, the timing integrity is best-effort against
adversarial code; the sandbox blocks the direct routes to faking the clock or the
output, but a candidate that patches the interpreter internals could still
distort the measured time.

\section{Lessons learned}

Three lessons shaped the final system. First, the checker must be tested as hard
as the candidate: the bug hunt found that the DFS certificate checker accepted a
parent tree no DFS produces and could hang on NaN times, and the fix is backed by
an exhaustive $n \le 4$ cross-check over 274{,}942 certificates. Second, the
two-tier grade is load bearing: the no-reflection BFS run of seed 3 passed the
$n \le 4$ search grade and failed 1 of 51{,}465 cases at $n = 5$. Third,
small-graph efficiency is not a proxy for large-graph efficiency: the
orchestrator's LBFS candidates were about twice as cheap as recomputing at
$n \le 5$ and about five times slower at $n = 128$. A fourth, smaller lesson came
from the execution record: a test whose plateau depended on measured wall-clock
work ratios failed once in six reruns on a loaded host, so timing must never
decide a functional assertion.

\section{Future work}

The most immediate step is to build fault corpora for the problems that have
checkers but no self-test, namely SCC, reachability, and MCS, so the
zero-false-negative claim extends beyond BFS, DFS, and LBFS. Second, more models
and more seeds, including a closed frontier model where available, would turn the
descriptive eval1 and eval3 comparisons into measurements. Third, seeding the LLM
sampling where a provider allows it would make the runs themselves reproducible,
not just the verifier. Fourth, larger $n$ via sampling with certificates would
push the bound outward while keeping the result honest. Fifth, continuous
integration for the test suites, which are currently run by hand, would gate
regressions. And sixth, full accessibility validation of the user interface,
which uses semantic controls but has not been tested against WCAG.
